The product / Lighthouse for agentic checkout

See where agents
get stuck.
Know what to fix.

Test a shopping journey.
Show the blocker. Fix it. Test again.

Designed to give merchants a score, evidence and prioritised fixes.

Solution, 15 seconds. Lighthouse is a familiar analogy for technical judges: a diagnostic report with actionable issues. For everyone else, explain the same idea as a check-up for an AI shopping journey. We want to show the failing step, rank the fixes, and rerun the journey after changes. The complete scanning and report workflow remains in progress. Technical appendix / design decisions

Reliable data.
Explicit failure paths.

Consistent prices
Integer minor units and a currency code.
Changed prices require fresh confirmation.
Safe retries
Idempotency keys identify repeated requests.
After timeouts, reconcile before another purchase.
Honest handoffs
Unsupported checkout returns requires_escalation.
The report must distinguish handoff from success.

The checkout guide documents retry and failure scenarios. Payments remain simulated.

Optional technical Q&A. The current checkout guide describes integer-cent prices, a changed-price confirmation flow, persistent authorization state before order placement, and timeout reconciliation against the merchant record. Capture failure cancels the merchant order and releases authorization. Integration scenarios include idempotency, lost responses, cancellation, and restart behavior. Sessions explicitly indicate simulated payments. UCP-shaped sessions do not assert full protocol conformance.
