## 1. Scope

**In scope:**
- **Scan & score (§6):**
  - the discovery cascade (`api` → `dom` → `computer_use`);
  - capability detection, including cart and checkout reachability;
  - the DOM interaction recipe;
  - the computer-use loop with screenshots streamed to Realtime;
  - scoring, the "after" projection and recommendations;
  - the scans API and MCP tools.
- Platform detection.
- T0 platform adapters (WooCommerce, Magento, Squarespace, SFCC, Shopify passthrough).
- The T2 engine (robots → sitemaps → JSON-LD).
- Normalization to `NormalizedProduct`.
- Idempotent upsert through `@/lib/db`.
- Crawl-run lifecycle and progress.
- Readiness (`computeReadiness(store, phase)`).
- Live offer re-verification (`verifyOffer`).
- Routes: `GET/POST /api/v1/stores`, `GET /api/v1/crawl-runs/{id}`, `POST /api/v1/scans`, `GET /api/v1/scans/{id}`.
- `registerCrawlTools`.
- Smoke scripts and unit tests.

**Stretch (designed-in, built last):**
- `mode: "full"` scans.
- Stagehand-based recipe repair.
- DOM-recipe catalog extraction (needs CCR §15.8).
- T3 microdata/OpenGraph.
- T4 Firecrawl.
- T5 LLM extraction.
- pgmq worker.
- Incremental re-crawl.

**Out of scope:**
- Checkout. WS4 owns it. WS4's `browser` connector *consumes* our `DomRecipe`.
- Search and serializers (WS3).
- UI (WS5).

**Hard rules:**
- **Never bypass bot protection.** A challenged store is `blocked`.
- **Never go past the cart in a scan.** Stop before payment (§6.5, §6.6).
- **Never place orders** on third-party stores.

**Never cut:** the Woo adapter, the JSON-LD engine, `POST /api/v1/stores` with live progress, the scan `api` probe and scoring (the landing flow), and the `dom` probe's structured stage.

## 4. Lifecycle and data flow

```
POST /api/v1/scans {url, mode?}                     (landing flow, WS5 "/")
  └─ startScan: normalizeStoreUrl → assertPublicHost → db.upsertStoreForUrl → reuse active scan?
       → db.upsertScan(status 'queued', probes: 3× pending) → stores.latest_scan_id
       → after(() => runScan(scan.id)) → 202 {scan_id, store_id, status_url, report_url}
runScan (inside after, ≤ 300 s; scan deadline 270 s)
  robots + detect (shared fetcher) → scans.platform
  checks (8 readiness checks) ─┐ run in parallel
  cascade: api → dom → computer_use; stop at first "passed"; untried → "skipped"
     every signal / probe status change / computer-use step → db.upsertScan({probes}) (≤ 2 writes/s) → Realtime
  score.ts: best_method, score, grade, after (projection), recommendations → status 'done'
  stores ← best_method, dom_recipe (if verified), latest_scan_id, readiness.before (setStoreReadiness)

"Make it agent-ready" → POST /api/v1/stores {store_id} (or {url})
  └─ startStoreCrawl: latest scan decides the strategy (§5.9 step 0); computer_use-only → 422
       → db.createCrawlRun → after(() => crawlStore(store.id, run.id))
crawlStore (≤ 300 s; pipeline deadline 240 s)
  claim run → runPipeline(hooks) → upsertStoreProducts in batches of 10 → progress + log
  finalize: store {status, platform, currency, name, product_count, strategy, checkout_connector}
            readiness.after = computeReadiness(store, "after"); scans.after (actual) on the latest scan
```

**State values:**

| Table.column | Values and who sets them |
|---|---|
| `scans.status` | `queued` → `running` → `done` \| `failed`. `failed` is only for infrastructure errors (DB, crash). A store that blocks us still ends `done`, with probes `blocked` and best `none`. |
| `scans.probes[].status` | `pending` → `running` → `passed` \| `partial` \| `failed` \| `blocked`. `skipped` means not tried. |
| `stores.status` | Crawl only: `pending` → `crawling` → `indexed` \| `failed` \| `blocked`. A failed re-crawl of an indexed store keeps `indexed`. Scans never change `stores.status`. |
| `stores.best_method` | Written after each scan: `api` \| `dom` \| `computer_use` \| `none`. |
| `crawl_runs.status` | `queued` → `running` → `succeeded` \| `failed`. A blocked store gives `failed` with `error = "blocked:<reason>"`. |

**`stores.metadata` keys WS2 writes** (free-form jsonb):
- `submitted_url`
- `platform_hint`: `"shopware"` and so on
- `detection: {confidence, signals[]}`
- `robots: {crawl_delay, content_signal}`
- `site_name`
- `block_reason`
- `computer_use_only: true`: set when `best_method = computer_use`.

**`stores.strategy`** (`StoreStrategy`) = `{ tier, adapter?, sampled_at }`. Extra jsonb keys `sample: {tried, ok}`, `partial`, `from_scan_id` are allowed.

**`crawl_runs.strategy`** (text) is one of:
- `"platform_api:woocommerce"`, …
- `"jsonld"`
- `"jsonld+recipe"` (stretch)
- `"render+jsonld"`
- `"llm"`

## 5. Module design (crawl)

### 5.1 `url.ts`

URL normalization is WS1's. `normalizeStoreUrl(raw, {allowPrivate})` returns `{domain, base_url, slug}` and throws `Error("invalid_store_url: …")`; map that to `AppError("validation_error", …)`. WS2 adds only what WS1 does not do:

```ts
export interface StoreTarget { origin: string; baseUrl: string; domainKey: string }   // domainKey === Store.domain
export function storeTarget(store: Pick<Store, "domain" | "base_url">): StoreTarget;
/** DNS-level SSRF guard (normalizeStoreUrl only rejects literal IPs / localhost). Throws AppError("validation_error"). */
export async function assertPublicHost(url: string, allowPrivate: boolean): Promise<void>;
export function canonicalizeProductUrl(u: string, base: string): string;
```

- **`assertPublicHost`**
  1. Run `dns.promises.lookup(host, { all: true })` (from `node:dns`).
  2. Reject if any address is in `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10`, `0.0.0.0/8`, `::1`, `fc00::/7` or `fe80::/10`.
  3. Allow only ports 80 and 443, or no port.
  4. Bypass the whole check when `flags.allowPrivateStoreHosts()` is true, or when the host equals `new URL(WOO_DEMO_URL).host`.
  5. It is called on the submitted URL, on **every redirect hop** (fetch), and on every top-level navigation in the browser probes (§6.4).
- **`canonicalizeProductUrl`**
  1. Resolve against the base and drop the `#fragment`.
  2. Remove `utm_*`, `gclid`, `fbclid`, `_pos`, `_sid`, `_ss`, `srsltid` and `ref`. Keep all other params.
  3. Remove a trailing `/` unless the path is `/`.
- **Handles** come from `handleFromUrl` in `@/lib/slug` (WS1, deterministic).
- **Redirects.** If the homepage redirects to another host (apex → www), `updateStore(id, { metadata })` records it, but `domain` and `base_url` are WS1-owned identity fields. Ask WS1 to allow `base_url` in `StorePatch` (§15.4).

### 5.2 `fetch.ts`: the polite fetcher

```ts
export type FetchKind = "html" | "json" | "xml" | "text";
export type BlockReason =
  | "robots" | "content_signal" | "challenge" | "forbidden" | "rate_limited"
  | "ssrf" | "too_large" | "timeout" | "network" | "deadline";
export interface FetchResult {
  url: string; finalUrl: string; status: number; ok: boolean;
  headers: Headers; body: string; ms: number;
  blocked: BlockReason | null; fromCache: boolean;
}
export interface FetchOpts {
  kind?: FetchKind; timeoutMs?: number; retries?: number;
  headers?: Record<string, string>; skipRobots?: boolean; noCache?: boolean;
}
export interface Fetcher {
  get(url: string, opts?: FetchOpts): Promise<FetchResult>;
  getJson<T = unknown>(url: string, opts?: FetchOpts): Promise<{ res: FetchResult; data: T | null }>;
  asFetch(): typeof fetch;          // fetch-compatible wrapper → CrawlContext.fetch
  robots: RobotsInfo | null;        // set by loadRobots()
  stats: { requests: number; ok: number; failed: number; blocked: number; challenged: number };
  userAgent: string; robotsToken: "ShoperZeroBot";
}
export function createFetcher(opts: {
  userAgent?: string; deadline?: number; allowPrivate?: boolean;
  perSecond?: number;       // default 2  (4 for WOO_DEMO_URL host)
  concurrency?: number;     // default 2  (4 for WOO_DEMO_URL host)
}): Fetcher;
```

**Behavior. Implement it exactly like this.**

1. **User agent.** Use `flags.crawlerUserAgent()` from `@/lib/env` (env `CRAWLER_USER_AGENT`; 00 §4.7 default `ShoperZeroBot/0.1 (+https://<app>/bot)`).
   - The UA always identifies ShoperZeroBot. We never send a spoofed browser UA in HTTP fetching; synthesis risk #8 requires an identifiable UA. The browser probes identify themselves with the `X-ShoperZero-Scan` header (§6.4).
   - Default headers:
     - `Accept` by kind:
       - html: `text/html,application/xhtml+xml;q=0.9,*/*;q=0.8`
       - json: `application/json`
       - xml: `application/xml,text/xml;q=0.9,*/*;q=0.5`
     - `Accept-Language: en-US,en;q=0.8`.
   - Let undici negotiate compression. Do not set `Accept-Encoding` by hand.
2. **Per-host queue.** Keep a `Map<host, PQueue>`, created lazily:
   ```ts
   new PQueue({ concurrency, interval: 1000, intervalCap: perSecond })
   ```
   - If robots has a crawl-delay `d` for our token (or `*`), use `new PQueue({ concurrency: 1, interval: Math.ceil(d * 1000), intervalCap: 1 })` instead.
   - We honor any delay. The time budget then limits how many products we get, and we log it.
3. **Deadline.** If `Date.now() > deadline - 2000` **before queueing**, return `blocked: "deadline"` without a request. The pipeline treats that as "stop".
4. **Robots.** Unless `skipRobots`, check `robots.isAllowed(url, "ShoperZeroBot")`. A `false` result returns `{status: 0, blocked: "robots"}` without a network call.
   - This applies to API endpoints too. A disallowed `/wp-json/` means no Woo adapter, so we fall back to T2.
   - `robots.txt` itself is fetched with `skipRobots`.
5. **Redirects.** Use `redirect: "manual"`, follow at most 5 hops, and call `assertPublicHost` on each `Location` (resolved against the current URL).
6. **Timeouts.** One `AbortSignal.timeout(timeoutMs)` covers the whole attempt, body included.
   - html: 15 s. json: 20 s. xml: 25 s. Readiness probes: 8 s.
   - A timeout gives `blocked: "timeout"` if there are no retries left.
7. **Body.**
   - Read with `await res.arrayBuffer()`.
   - Reject with `blocked: "too_large"` when the size exceeds 3 MB for html/json, or 12 MB for xml. Check `content-length` first when it is present.
   - If the first two bytes are `0x1f 0x8b` (raw `.gz` sitemap), decompress: `new Response(new Blob([buf]).stream().pipeThrough(new DecompressionStream("gzip"))).text()`. Otherwise use `new TextDecoder("utf-8").decode(buf)`.
     - Also honor a `charset=` in `content-type` if it is not utf-8, e.g. `windows-1252`, via `new TextDecoder(label)`. Fall back to utf-8 when the label is unsupported.
8. **Retries** (default `retries: 2`, so 3 attempts):
   - **Retry on:** network errors (`TypeError` from fetch, `ECONNRESET`, `ETIMEDOUT`, `UND_ERR_*`), 408, 425, 429, 500, 502, 503 and 504, but **not** when challenge markers are present.
   - **Backoff:** `Retry-After` (seconds or HTTP-date), capped at 10 s. Otherwise `750 * 2 ** attempt + random(0..250)` ms.
   - **Never retry:** 401, 403, 404, 410, or a challenge.
   - **After two 429s** on a host, halve that host's `intervalCap`, with a minimum of 1 request per 2 s. Log it at `warn`.
9. **Challenge detection** (`detectChallenge(status, headers, body)`). The first match sets `blocked`:

   | Signal | Reason |
   |---|---|
   | header `cf-mitigated: challenge` | challenge |
   | body contains `Just a moment...`, `cf-chl-`, `/cdn-cgi/challenge-platform/`, or `challenges.cloudflare.com` | challenge |
   | header `x-datadome` or `x-dd-b`, or body contains `captcha-delivery.com` or `geo.captcha-delivery.com` | challenge |
   | body contains `_Incapsula_Resource` or `Incapsula incident ID` | challenge |
   | body contains `px-captcha` or `_pxhd`, or header `x-px-` | challenge |
   | status 403, header `server` matches `/AkamaiGHost/i`, or body `Access Denied` + `Reference #` | forbidden |
   | status 403 (other) | forbidden |
   | status 429 after retries | rate_limited |

   Only scan the first 64 KB of the body for markers. A 200 page can carry a challenge (Cloudflare interstitial), so run the check on every response. This follows research 04 §6 and 05 `looksUnrendered`.
10. **Cache.** Keep an in-memory `Map<url, FetchResult>` per fetcher, one fetcher per crawl, so the homepage, robots and readiness probes are fetched once. Do not cache blocked or 5xx results. `noCache` bypasses it.
11. **`asFetch()`** returns a `typeof fetch` wrapper for `CrawlContext.fetch` (contract §6):
    - It calls `get(url, {kind: guessKind(init)})` and returns `new Response(body, { status: res.status || 599, headers })`.
    - If the result is blocked, it sets `x-shoperzero-blocked: <reason>` and status 403 (robots, content_signal, challenge, forbidden) or 599 (the rest).
    - `Response` only accepts 200–599, so never pass 0.
    - Only GET is supported. Any other method throws `AppError("bad_request", "crawler is read-only")`, because ingestion never writes to merchants. The **only** non-GET traffic WS2 ever sends to a merchant is the browser-driven add-to-cart in the scan's DOM verification and computer-use probes (§6), which never go past the cart.

    Adapters use two helpers on top of `ctx.fetch`:
    ```ts
    export async function getText(ctx: CrawlContext, url: string): Promise<{ status: number; ok: boolean; body: string; headers: Headers; blocked: string | null }>;
    export async function getJson<T>(ctx: CrawlContext, url: string): Promise<{ status: number; ok: boolean; data: T | null; headers: Headers; blocked: string | null }>;
    ```
    `getJson` returns `data: null` when parsing fails or when the content is HTML (the body starts with `<`).
12. **Circuit breaker** (enforced in `pipeline.ts`). Abort with `blocked: challenge` if ≥ 5 of the first 10 page fetches are challenge/forbidden, or if the homepage itself is challenged.

### 5.3 `robots.ts`

```ts
import robotsParser from "robots-parser";
export interface RobotsInfo {
  url: string; status: number;                       // status of robots.txt fetch
  isAllowed(url: string, ua?: string): boolean;      // ua default "ShoperZeroBot"
  crawlDelaySec: number | null;                      // for ShoperZeroBot, else "*"
  sitemaps: string[];                                // absolute URLs from Sitemap: lines
  contentSignal: Record<string, "yes" | "no"> | null; // group for our token, else "*"
  blocksUs: null | "robots" | "content_signal";
}
export async function loadRobots(fetcher: Fetcher, origin: string): Promise<RobotsInfo>;
```

**Status rules** (RFC 9309):

| robots.txt result | Treatment |
|---|---|
| 200 | Parse it. |
| 4xx, including 404 | Allow all. |
| 5xx or network failure after retries | Disallow all: `blocksUs='robots'`, log `"robots.txt unreachable (RFC 9309: treat as disallow)"`. |
| Challenge | Store `blocked:challenge`. |

**Parsing:**
1. Parse with `robotsParser(url, body)`.
2. `blocksUs='robots'` when `!isAllowed(baseUrl + "/", "ShoperZeroBot")` **and** `!isAllowed(<any sampled product URL>)`.
   - In practice, check the homepage at robots time, then re-check each URL in the fetcher.
3. **Content-Signal** (contentsignals.org; `robots-parser` ignores unknown lines):
   - Scan the lines manually and track the current `User-agent:` group(s).
   - For each `Content-Signal:` line in a group that applies to `ShoperZeroBot` or `*`, parse `key=value` pairs separated by commas.
   - `ai-input=no` sets `blocksUs='content_signal'`. A crawl then ends with the store `blocked` (`block_reason='content_signal'`); a scan marks every probe `blocked`.

**Per page.** If a PDP response has `X-Robots-Tag` containing `noai` or `none`, skip that URL, count it `pages_failed` and log it at `info`.

### 5.4 `detect.ts`: fingerprints and scoring

```ts
export interface DetectionResult {
  platform: Platform;                // contracts Platform
  confidence: number;                // 0..1
  signals: string[];                 // e.g. ["header:x-bc-store-id", "probe:woo_store_api"]
  hint: string | null;               // "shopware" | "opencart" | "ecwid" when platform === "custom"
  adapter: PlatformAdapter | null;   // set only when a T0 adapter is usable (probe passed)
  scores: Partial<Record<string, number>>;
  probes: Record<string, { url: string; status: number; ok: boolean }>;
  homepage: { finalUrl: string; status: number; html: string; headers: Headers };
  siteName: string | null;
}
export async function detectPlatform(fetcher: Fetcher, target: StoreTarget): Promise<DetectionResult>;
```

**Algorithm:**
1. `GET baseUrl + "/"` (kind html).
   - If it is blocked, return `platform: "unknown"`, confidence 0. The pipeline marks the store `blocked` (challenge/forbidden) or `failed` (timeout/network).
   - If the final URL's host differs from the submitted host, e.g. apex → www, set `target.origin` and `target.baseUrl` from the final URL. Keep `domainKey` unchanged. Persist the new `base_url` in metadata.
2. **Passive signals.** Each platform scores a noisy-OR over its matched signals: `score = 1 − Π(1 − wᵢ)`.
   - Inputs:
     - Headers, lower-cased.
     - Cookie **names** parsed from `headers.getSetCookie()`.
     - Up to 512 KB of HTML.
     - `meta[name=generator]` content.
3. **Probes.**
   - Sort the platforms that have `score ≥ 0.25` and a probe, in descending order, and probe the top 2.
   - If none reaches 0.25, run the **blind probes** `woocommerce`, `magento` and `shopify`, in that order, and stop at the first hit. This catches headless Magento Edge Delivery Services (EDS) such as bulk.com, which has no Luma fingerprint.
   - A successful probe adds a signal with w = 0.95.
   - A probe that fails (4xx, 5xx, robots, challenge) adds nothing. The platform may still win on passive signals, but `adapter` stays `null`.
4. **Decision.**
   - `platform` = the argmax over the Platform-union platforms if its score is ≥ 0.5.
   - Otherwise, if a hint-only platform (shopware, opencart, ecwid) scores ≥ 0.5, use `platform: "custom"` with `hint` set.
   - Otherwise use `"custom"`.
   - `adapter` = `adapters[platform]` when that platform has an adapter **and** its probe succeeded. SFCC has no probe; for it, "site id extracted" counts as the probe.
5. **Site name.** Take the first non-empty of:
   - JSON-LD `Organization.name` or `WebSite.name`.
   - `meta[property="og:site_name"]`.
   - `<title>` split on ` | `, ` – `, ` - `, keeping the shortest segment of 3 or more characters.

### 5.5 Adapters (`adapters/*.ts`)

The common rules for every adapter:
- Implement the contract's `PlatformAdapter`: `platform`, `detect`, `listProducts` (an async generator) and `fetchOffer`.
- `listProducts` yields products **as they are mapped**. The caller stops consuming when it hits `max` or the deadline. An adapter must still stop by itself at `opts.max`.
- Each product goes through `finalizeProduct()` (§5.8) before it is yielded. Skip products that fail finalization and log them.
- **Throw `AdapterError('unavailable', status)` only when the first page fails.** On that error the pipeline falls back to T2. A failure on a later page ends the stream quietly with a warn log.
- `source: "platform_api"`. `raw` is the source item, trimmed to ≤ 50 KB by `finalizeProduct`.
- `checked_at` is the ISO time of the page fetch.

#### 5.5.1 WooCommerce (Store API) — LIVE-OK in 04

**API base.** Use whichever prefix answered the probe:
- `A = {base}/wp-json/wc/store/v1`, or
- `A' = {base}/?rest_route=/wc/store/v1` (query params then join with `&`).

Build URLs with `wooUrl(apiBase, path, params)`.

**Listing:**

```
GET {A}/products?per_page=100&page={N}&orderby=date&order=desc
  response headers: X-WP-Total, X-WP-TotalPages
```

**Pagination:**
- Continue while `page <= X-WP-TotalPages` and emitted < max.
- If the header is missing, continue while `data.length === 100`.
- `per_page` max is 100.

**Variations.**
- The listing returns `variations: [{id, attributes: [{name, value}]}]` with **no** prices. Collect up to 30 variation ids per variable product on the page.
- **Batch fetch (UNVERIFIED):** `GET {A}/products?type=variation&include={ids,comma}&per_page=100`.
  - The Store API documents `type` (including `variation`) and `include[]` filters, but we did not check variations in a collection live.
- **Fallback 1:** `GET {A}/products/{variationId}` per id. Cap it at 30 per product and 300 per run.
- **Fallback 2:** synthesize variants from the parent. Take `prices.price` for each variation and use the parent's `is_in_stock`. Set `strategy.partial = true` and log at warn.

**Product mapping** (raw Woo item → `NormalizedProduct`):

| NormalizedProduct | Woo Store API field | Notes |
|---|---|---|
| `external_id` | `String(id)` | |
| `url` | `permalink` | `canonicalizeProductUrl` |
| `handle` | `slug` | Fallback: `handleFromUrl(permalink)` from `@/lib/slug`. |
| `title` | `name` | `decodeEntities`; names contain `&#8211;` etc. |
| `description_html` | `description` or `short_description` | |
| `description_text` | `htmlToText(description_html)` | |

| `product_type` | `categories[0]?.name ?? null` | Decode entities. |
| `category` | deepest category name: `categories.at(-1)?.name ?? null` | |
| `tags` | `tags[].name` | |
| `images` | `images[].{src → url, alt}` | Hotlinked. |
| `options` | `attributes.filter(a => a.has_variations).map(a => ({ name: a.name, values: a.terms.map(t => t.name) }))` | |

**Woo money.** Woo prices are **strings in the store's configured minor unit**, and that unit can differ from ISO. porterandyork uses `currency_minor_unit: 0` for USD, so `"115"` means $115.

```ts
import { rescaleMinor } from "@/lib/money";   // WS1: store minor unit → ISO exponent
function wooMoney(amount: string, p: { currency_code: string; currency_minor_unit: number }): Money {
  const currency = p.currency_code.toUpperCase();
  return { amount: rescaleMinor(amount, p.currency_minor_unit, currency), currency };
}
// porterandyork: "115", minor_unit 0, USD → 11500
```

**`fetchOffer(ctx, product, variantExternalId)`:**
1. `GET {A}/products/{variantExternalId ?? product.external_id}`.
2. Map it as above.
3. A 404 throws `OfferVerificationError` with reason `variant_gone` (§5.12).

**Code sketch (pagination):**

```ts
// src/lib/crawl/adapters/woocommerce.ts
import type { CrawlContext, NormalizedProduct, PlatformAdapter } from "@/lib/contracts";
import { getJson } from "../fetch";
import { AdapterError } from "../errors";
import { finalizeProduct } from "../normalize";
import { scorePlatform } from "../detect";

const MAX_VARIATIONS_PER_PRODUCT = 30;

export async function resolveWooApi(ctx: CrawlContext): Promise<string | null> {
  for (const api of [`${ctx.baseUrl}/wp-json/wc/store/v1`, `${ctx.baseUrl}/?rest_route=/wc/store/v1`]) {
    const r = await getJson<unknown[]>(ctx, wooUrl(api, "/products", { per_page: 1 }));
    if (r.ok && Array.isArray(r.data)) return api;
  }
  return null;
}
export function wooUrl(api: string, path: string, params: Record<string, string | number>) {
  const qs = new URLSearchParams(Object.entries(params).map(([k, v]) => [k, String(v)])).toString();
  return api.includes("?rest_route=") ? `${api}${path}&${qs}` : `${api}${path}?${qs}`;
}

export const woocommerce: PlatformAdapter = {
  platform: "woocommerce",
  async detect(ctx) {
    const passive = scorePlatform(ctx, "woocommerce");
    return (await resolveWooApi(ctx)) ? 1 - (1 - passive) * 0.05 : passive;
  },
  async *listProducts(ctx, { max }) {
    const api = await resolveWooApi(ctx);
    if (!api) throw new AdapterError("unavailable", "woocommerce", 0);
    let page = 1, totalPages = Number.POSITIVE_INFINITY, emitted = 0;
    while (page <= totalPages && emitted < max) {
      const checkedAt = new Date().toISOString();
      const r = await getJson<WooProduct[]>(ctx, wooUrl(api, "/products", { per_page: 100, page, orderby: "date", order: "desc" }));
      if (!r.ok || !Array.isArray(r.data)) {
        if (page === 1) throw new AdapterError("unavailable", "woocommerce", r.status);
        break;                                                     // later page failed: stop quietly (logged by caller)
      }
      const hdr = r.headers.get("x-wp-totalpages");
      totalPages = hdr ? Number(hdr) : r.data.length === 100 ? page + 1 : page;
      const ids = r.data.filter((p) => p.type === "variable")
        .flatMap((p) => p.variations.slice(0, MAX_VARIATIONS_PER_PRODUCT).map((v) => v.id));
      const variations = await fetchWooVariations(ctx, api, ids);   // Map<id, WooProduct>; batch → per-id → empty
      for (const item of r.data) {
        if (emitted >= max) return;
        if (item.type === "grouped" || item.type === "external") continue;
        const np = finalizeProduct(mapWooProduct(item, variations, checkedAt), { baseUrl: ctx.baseUrl });
        if (np.ok) { emitted++; yield np.product; }
      }
      page++;
    }
  },
  async fetchOffer(ctx, product, variantExternalId) { /* GET {api}/products/{id} → mapWooVariant(...).offer */ throw new Error("todo"); },
};
declare function fetchWooVariations(ctx: CrawlContext, api: string, ids: number[]): Promise<Map<number, WooProduct>>;
declare function mapWooProduct(p: WooProduct, v: Map<number, WooProduct>, checkedAt: string): Omit<NormalizedProduct, "handle"> & { handle?: string };
type WooProduct = { id: number; type: string; variations: { id: number; attributes: { name: string; value: string }[] }[] } & Record<string, any>;
```

#### 5.5.2 Magento 2 / Adobe Commerce (GraphQL) — catalog LIVE-OK in 04

**Endpoint.** `GET {base}/graphql?query={urlencoded}` (GET is cacheable and was LIVE-OK). Send header `Content-Type: application/json` as well. If GET returns 404 or 405, fall back to `POST` with `{ "query": ... }`. POST here is a read-only query and is the documented transport.

**Store config.** It comes from the probe: `base_currency_code`, `product_url_suffix` (default `.html`), `locale`.

**Page query.** Substitute `{P}` and `{S}`, with `S = 50`:

```graphql
{ products(search: "", pageSize: {S}, currentPage: {P}) {
    total_count
    page_info { current_page total_pages page_size }
    items {
      __typename uid sku name url_key url_suffix canonical_url stock_status
      description { html } short_description { html }
      image { url label } media_gallery { url label }
      categories { name }
      price_range {
        minimum_price { final_price { value currency } regular_price { value currency } }
      }
      ... on ConfigurableProduct {
        configurable_options { attribute_code label values { uid label value_index } }
        variants {
          attributes { code label uid value_index }
          product { uid sku name stock_status image { url }
            price_range { minimum_price { final_price { value currency } regular_price { value currency } } } }
        }
      }
    } } }
```

**Fallbacks, in order:**
1. **Errors.** If the response has `errors[]` whose message matches `/Cannot query field|complexity|depth/i`, retry that page with the **safe query**: drop `canonical_url`, `categories`, `short_description` and `media_gallery`, and set `S = 20`.
2. **Empty search.** If `search:""` errors or returns `total_count: 0`, walk the category list:
   - `{ categoryList { uid name product_count children { uid name product_count } } }`
   - Then page `products(filter: { category_uid: { in: [uid] } }, pageSize, currentPage)` for the top 5 categories by `product_count`.
   - Dedupe by sku.
3. **WAF.** A 403 or challenge on `/graphql` (seen on lampenwelt.de) is `AdapterError('unavailable')`, and the pipeline falls back to T2.

**Pagination.** Stop at `currentPage >= total_pages`, at emitted ≥ max, or on an empty `items`. Some stores cap `total_count`, so trust `items.length` over it.

**Product mapping:**

| NormalizedProduct | Magento field |
|---|---|
| `external_id` | `sku` |
| `url` | 1) `canonical_url`, resolved against `base + "/"`; 2) otherwise `${base}/${url_key}${url_suffix ?? storeConfig.product_url_suffix ?? ".html"}`. **UNVERIFIED for EDS storefronts** (bulk.com may route PDPs differently): during sampling, GET the first mapped URL, and if it 404s build `url_key → URL` from sitemap discovery (`sitemap.ts`) and look each product up by url_key substring; products with no match keep the constructed URL. |
| `handle` | `url_key` |
| `title` | `name` (decode entities) |

### 5.6 `sitemap.ts`: product URL discovery

```ts
export interface SitemapUrl { loc: string; lastmod?: string; image?: string }
export interface DiscoveryResult {
  urls: SitemapUrl[];                  // product-ish, canonicalized, deduped, robots-allowed
  sitemapsFetched: string[];
  productSitemapFound: boolean;        // a child sitemap name matched PRODUCT_SITEMAP_HINT
  source: "robots" | "guess" | "html_links";
}
export async function discoverProductUrls(
  fetcher: Fetcher, target: StoreTarget, robots: RobotsInfo,
  opts: { platform: Platform; hint?: string | null; max: number /* e.g. maxProducts * 4, cap 5000 */; homepageHtml: string },
): Promise<DiscoveryResult>;
```

**Roots, in order:**
1. `robots.sitemaps`.
2. If there are none, platform guesses, all at the origin:
   - woocommerce: `/product-sitemap.xml`, `/sitemap_index.xml`, `/wp-sitemap.xml`
   - bigcommerce: `/xmlsitemap.php`
   - wix: `/store-products-sitemap.xml`, `/sitemap.xml`
   - prestashop: `/1_index_sitemap.xml`, `/sitemap.xml`
   - shopify: `/sitemap.xml`
   - sfcc: `/sitemap_index.xml`, `/sitemap_0.xml`
3. Always append `/sitemap.xml`, `/sitemap_index.xml`, `/sitemap-index.xml`.

**Walk.**
- A BFS queue with product sitemaps first.
- Budgets:
  - ≤ 30 sitemap fetches.
  - ≤ 25 s wall-clock in discovery.
  - Stop early once `productish.length ≥ opts.max`.
- XML parser:
  ```ts
  new XMLParser({ ignoreAttributes: true, removeNSPrefix: true, parseTagValue: false, trimValues: true,
                  isArray: (n) => ["sitemap", "url", "image"].includes(n) })
  ```
- A body that does not start with `<` (after BOM and whitespace) is treated as a **plain-text sitemap**: one URL per line.
- An HTML body (`<html`) is skipped. Many soft-404s return 200 HTML.

**Child sitemap ordering:**
- `PRODUCT_SITEMAP_HINT = /product|prod[_-]|sitemap_products|type=products|catalog|store-products|shop/i` goes first.
- Skip `NON_PRODUCT_SITEMAP = /post|page(?!s?=)|categor|collection|tag|author|blog|article|news|brand|cms|image|video|faq|store-locat/i` unless nothing else exists.
- Among the rest, alphabetical, capped at 5.

**URL scoring** (`productUrlScore(url, platform)`). Score ≤ 0 means not product-ish.

| Pattern | Score |
|---|---|
| `/(product|products|p|item|dp)/[^/]+` | +3 |
| `/product-page/` (wix) | +3 |
| `/shop/p/` (squarespace) | +3 |
| `[-_/]p\d{3,}` or `/\d{4,}\.html$` | +2 |
| `\.html$` when platform ∈ {magento, sfcc} | +2 |
| `/(category|categories|collections?|tag|tags|blog|news|pages?|account|cart|checkout|search|wishlist|login|cms|brands?)(/|$)` | −5 |
| extension `\.(jpg|jpeg|png|gif|webp|pdf|xml)$` | −10 |
| path depth 0 (homepage) | −10 |

**Filtering:**
- If the URL came from a child sitemap that matched `PRODUCT_SITEMAP_HINT`, accept every URL with score > −5.
- Otherwise keep score > 0. If fewer than 10 survive, keep every URL with score > −5 and let sampling decide.

**Clean-up:**
- Dedupe by `canonicalizeProductUrl`.
- Keep only same-site URLs (host equal to the origin host, or its www/apex twin) whose path is under `baseUrl`'s path prefix.
- Drop URLs `robots.isAllowed` rejects.

**Order.** Keep sitemap order; it is deterministic. If more than `max` exist, keep the first `max`. `lastmod` sorting is stretch (incremental).

**No sitemap at all (html_links fallback):**
1. Parse `<a href>` on the homepage.
2. Collect product-ish links (score > 0).
3. Fetch up to 5 category-like links: same host, path depth 1–2, containing `shop|category|collection|store|products`. Collect their product-ish links too.
4. Cap at 20 discovery pages.

Stretch T4 adds Firecrawl `map` here.

**Code sketch:**

```ts
// src/lib/crawl/sitemap.ts
import { XMLParser } from "fast-xml-parser";
import type { Platform } from "@/lib/contracts";
import type { Fetcher } from "./fetch";
import type { RobotsInfo } from "./robots";
import type { StoreTarget } from "./url";
import { canonicalizeProductUrl } from "./url";

const xml = new XMLParser({ ignoreAttributes: true, removeNSPrefix: true, parseTagValue: false, trimValues: true,
  isArray: (n) => n === "sitemap" || n === "url" || n === "image" });
const PRODUCT_SITEMAP_HINT = /product|prod[_-]|sitemap_products|type=products|catalog|store-products|shop/i;
const NON_PRODUCT_SITEMAP = /post|page(?!s?=)|categor|collection|tag|author|blog|article|news|brand|cms|image|video|faq|store-locat/i;
const GUESSES: Partial<Record<Platform, string[]>> = {
  woocommerce: ["/product-sitemap.xml", "/sitemap_index.xml", "/wp-sitemap.xml"],
  bigcommerce: ["/xmlsitemap.php"], wix: ["/store-products-sitemap.xml"],
  prestashop: ["/1_index_sitemap.xml"], sfcc: ["/sitemap_index.xml", "/sitemap_0.xml"],
};

export async function discoverProductUrls(f: Fetcher, t: StoreTarget, robots: RobotsInfo,
  opts: { platform: Platform; max: number; homepageHtml: string }) {
  const started = Date.now();
  const roots = robots.sitemaps.length ? robots.sitemaps
    : [...(GUESSES[opts.platform] ?? []), "/sitemap.xml", "/sitemap_index.xml", "/sitemap-index.xml"].map((p) => t.origin + p);
  const queue: { url: string; productHint: boolean }[] = roots.map((u) => ({ url: u, productHint: PRODUCT_SITEMAP_HINT.test(u) }));
  const seen = new Set<string>(); const fetched: string[] = [];
  const out = new Map<string, { loc: string; lastmod?: string; image?: string; score: number; fromProductSitemap: boolean }>();
  let productSitemapFound = false;

  while (queue.length && fetched.length < 30 && Date.now() - started < 25_000) {
    const { url, productHint } = queue.shift()!;
    if (seen.has(url)) continue; seen.add(url);
    const res = await f.get(url, { kind: "xml" });
    if (res.blocked === "deadline") break;
    if (!res.ok) continue;
    fetched.push(url);
    const body = res.body.replace(/^﻿/, "").trimStart();
    if (/^<!doctype html|^<html/i.test(body)) continue;             // soft 404
    if (!body.startsWith("<")) {                                     // plain-text sitemap
      for (const line of body.split(/\r?\n/)) addUrl(line.trim(), undefined, undefined, productHint);
      continue;
    }
    let doc: any; try { doc = xml.parse(body); } catch { continue; }
    if (doc.sitemapindex) {
      const kids: string[] = (doc.sitemapindex.sitemap ?? []).map((s: any) => String(s.loc ?? "").trim()).filter(Boolean);
      const prod = kids.filter((k) => PRODUCT_SITEMAP_HINT.test(k));
      const rest = kids.filter((k) => !PRODUCT_SITEMAP_HINT.test(k) && !NON_PRODUCT_SITEMAP.test(k)).sort().slice(0, 5);
      if (prod.length) productSitemapFound = true;
      queue.unshift(...prod.map((u) => ({ url: u, productHint: true })));
      if (!prod.length) queue.push(...rest.map((u) => ({ url: u, productHint: false })));
    } else if (doc.urlset) {
      for (const u of doc.urlset.url ?? []) addUrl(String(u.loc ?? "").trim(), u.lastmod, u.image?.[0]?.loc, productHint);
    }
    if ([...out.values()].filter((u) => u.score > 0 || u.fromProductSitemap).length >= opts.max) break;
  }

  function addUrl(loc: string, lastmod?: string, image?: string, fromProductSitemap = false) {
    if (!/^https?:\/\//i.test(loc)) return;
    const c = canonicalizeProductUrl(loc, t.baseUrl);
    if (!sameSite(c, t) || !robots.isAllowed(c) || out.has(c)) return;
    out.set(c, { loc: c, lastmod, image, score: productUrlScore(c, opts.platform), fromProductSitemap });
  }
  const all = [...out.values()];
  let picked = all.filter((u) => (u.fromProductSitemap ? u.score > -5 : u.score > 0));
  if (picked.length < 10) picked = all.filter((u) => u.score > -5);
  return { urls: picked.slice(0, opts.max).map(({ loc, lastmod, image }) => ({ loc, lastmod, image })),
           sitemapsFetched: fetched, productSitemapFound, source: robots.sitemaps.length ? "robots" : "guess" } as const;
}
declare function productUrlScore(u: string, p: Platform): number;
declare function sameSite(u: string, t: StoreTarget): boolean;
```

`html_links` is used only when this returns 0 URLs.

### 5.7 `jsonld.ts`: JSON-LD → `NormalizedProduct`

```ts
export type JsonLdMiss = "no_jsonld" | "no_product" | "no_price" | "no_currency" | "invalid";
export interface JsonLdResult { product: NormalizedProduct | null; miss: JsonLdMiss | null; nodes: number }
export function extractJsonLdProduct(html: string, pageUrl: string, opts: {
  defaultCurrency: string | null;   // store currency learned so far (mode of previous products), else null
  checkedAt: string;
  baseUrl: string;
}): JsonLdResult;
export function parseJsonLdNodes(html: string): Record<string, unknown>[];   // also used by readiness + site name
```

**Parsing rules.** Each handles a quirk seen on real sites (05 §2).

1. **Script selection.** Use `script[type*="ld+json" i]`. It matches `application/ld+json` with any casing and with `; charset=`.
2. **Tolerant JSON (`safeJson`).**
   - Strip `<!--`, `-->`, `//<![CDATA[`, `//]]>` and a trailing `;`.
   - Try `JSON.parse`.
   - Then retry with control characters replaced by spaces and trailing commas removed (`/,\s*([}\]])/g`).
   - Then retry concatenated objects wrapped: `[` + `s.replace(/}\s*{/g, "},{")` + `]`.
   - If all three fail, skip the block and count a parse error.
3. **Flattening (`collectNodes`).**
   - Arrays, `@graph`, `mainEntity` and `itemListElement[].item` (or the element itself) all yield nodes.
   - Do **not** flatten `hasVariant` or `offers`. They are read in context.
4. **`@id` references.**
   - Index every node that has an `@id`.
   - `deref(v)`: when `v` is an object whose only meaningful key is `@id`, return the indexed node.
   - Apply it to `hasVariant[]`, `isVariantOf`, `offers`, `brand` and `image`.
5. **Types.**
   - `typesOf(n)` normalizes a string or array, strips `http(s)://schema.org/` and `schema:`.
   - Product nodes are `Product` or `IndividualProduct`. `ProductModel` is ignored.
   - A group is `ProductGroup`.
6. **Choosing the main entity.**
   - **With a group:** the group whose `url` canonicalizes to `pageUrl`, else the first group.
     - Its variants are `deref(hasVariant[])`, plus any product node whose `isVariantOf` derefs to the group or whose `inProductGroupWithID === group.productGroupID`.
   - **Without a group:** the main product is the product node whose `url` (or `offers.url`) canonicalizes to `pageUrl`, else the first product with `offers`, else the first product.
     - Variants are product nodes that share the main's `inProductGroupWithID` or `isVariantOf`. The main is included.
     - **Offer-variants:** if there is still only one node but its offers, flattened (including `AggregateOffer.offers[]`), are ≥ 2 **with distinct `sku` or `name`**, each such offer becomes a variant. Its title is `offer.name` minus the product name prefix, or its sku.
     - Otherwise there is a single variant.
   - **Listing pages** with many unrelated `Product` nodes (e.g. `ItemList`) and no URL match return `miss: "no_product"`. We only extract PDPs.
7. **Offers (`readOffers(offers, inheritedCurrency)`)**, applied to each variant node:
   - Flatten `Offer | Offer[] | AggregateOffer`. `AggregateOffer` with nested `offers` is replaced by its children. Without children it becomes a pseudo-offer: `{price: lowPrice, priceCurrency, availability}`.
   - **Price:** `offer.price ?? offer.lowPrice ?? saleSpec?.price ?? (specs.length === 1 ? specs[0].price : undefined)`.
     - `specs = deref(priceSpecification[])`.
     - `listSpec` = the spec whose `priceType` matches `/StrikethroughPrice|ListPrice|MSRP|SRP/i`.
     - `saleSpec` = the first other spec that has a `price`.
   - **compare_at** = `listSpec.price` if it is greater than the price.
   - **Price parse:** `parsePrice(raw, currency)` from `@/lib/money` (WS1). It treats a lone `.` as the decimal separator, which matches schema.org. Values ≤ 0 or unparseable count as missing ("call for price").
   - **Currency:** `offer.priceCurrency ?? saleSpec?.priceCurrency ?? listSpec?.priceCurrency ?? inheritedCurrency ?? pageMetaCurrency ?? opts.defaultCurrency`.
     - `pageMetaCurrency` = `meta[itemprop=priceCurrency]` or `meta[property="product:price:currency"]`.
     - Uppercase it and require `/^[A-Z]{3}$/`.
   - **Best offer:** among priced offers, prefer `in_stock`, then the lowest price.
   - **Availability mapping.** Take the last path segment, lowercase it, and remove non-letters:

     | schema.org value(s) | Availability |
     |---|---|
     | `InStock`, `LimitedAvailability`, `OnlineOnly`, `in_stock`, `instock`, `true` | `in_stock` |
     | `PreOrder`, `PreSale`, `BackOrder` | `preorder` |
     | `OutOfStock`, `SoldOut`, `Discontinued`, `InStoreOnly` | `out_of_stock` |
     | missing or anything else | `unknown` |

     `InStoreOnly` maps to `out_of_stock` on purpose: an agent cannot buy it online. This differs from 05, which mapped it to `in_stock`.
8. **Fields:**
   - `title`: `name`, decoded and trimmed. An empty title is a miss `invalid`.
   - `description_html`: `description`. JSON-LD descriptions are usually text. If it contains `<`, keep it as HTML. Otherwise use `null` for HTML and put it in `description_text`.
   - `brand`: string, or `brand.name`, or `manufacturer.name`.
   - `images`: `image` may be a string, a string[], an `ImageObject{url|contentUrl}` or an array of those. Resolve to absolute URLs, dedupe, keep ≤ 12.
   - `gtin`: first of `gtin`, `gtin13`, `gtin12`, `gtin14`, `gtin8`, or `isbn` for books. Store it on the variant. The product-level `gtin` column is set by WS1 from the first variant.
   - `sku`: `sku ?? mpn ?? null`.
   - `external_id`:
     - Product: `productGroupID ?? productID ?? sku ?? mpn ?? null`.
     - Variant: `sku ?? productID ?? gtin ?? offer.sku ?? null`. A null stays null; the db derives the key with `variantKey()` (00 §4.2).
   - **Options:**
     - `variesBy` values (strip the schema prefix) are title-cased keys: `color` → `Color`, `size` → `Size`, `material`, `pattern`, `suggestedAge`, `suggestedGender`.
     - Values come from `variant[prop]`, or `.name` if it is an object.
     - Without `variesBy`, use whichever of `color`, `size`, `material` or `pattern` exist, plus `additionalProperty[{name, value}]` for the variant nodes.
   - `category`: `category` (a string, or the last segment of a `>` path).
   - `product_type`: `null`.
   - `url`: `pageUrl` (canonical). Each variant's `offer.url` is `variant.url ?? offer.url ?? pageUrl`.
   - `raw`: `{ nodes: [main, ...variantNodes] }`.
9. **Misses.**
   - `no_jsonld`: no parsable blocks.
   - `no_product`: no Product or ProductGroup.
   - `no_price`: no variant has a price.
   - `no_currency`: price present, no currency.

   Sampling uses these to decide the tier (§5.9). Readiness uses the hit ratio.

```ts
// src/lib/crawl/jsonld.ts
import * as cheerio from "cheerio";
import type { Availability, Money, NormalizedProduct, NormalizedVariant } from "@/lib/contracts";
import { parsePrice } from "@/lib/money";
import { decodeEntities, finalizeProduct } from "./normalize";
import { canonicalizeProductUrl } from "./url";

type N = Record<string, any>;
const arr = <T,>(v: T | T[] | null | undefined): T[] => (v == null ? [] : Array.isArray(v) ? v : [v]);
const PREFIX = /^(?:https?:)?\/\/schema\.org\/|^schema:/i;
export const typesOf = (n: unknown) => (n && typeof n === "object" ? arr((n as N)["@type"]).map((t) => String(t).replace(PREFIX, "")) : []);
const is = (n: unknown, ...t: string[]) => typesOf(n).some((x) => t.includes(x));

export function safeJson(text: string): unknown {
  const t = text.replace(/^\s*(?:<!--|\/\/\s*<!\[CDATA\[)/, "").replace(/(?:-->|\/\/\s*\]\]>)\s*$/, "").trim().replace(/;\s*$/, "");
  for (const cand of [t, t.replace(/[\u0000-\u001F]+/g, " ").replace(/,\s*([}\]])/g, "$1")]) {
    try { return JSON.parse(cand); } catch {}
  }
  try { return JSON.parse(`[${t.replace(/}\s*{/g, "},{")}]`); } catch { return null; }
}

export function parseJsonLdNodes(html: string): N[] {
  const $ = cheerio.load(html);
  const out: N[] = [];
  const walk = (v: unknown) => {
    for (const n of arr(v as N | N[])) {
      if (!n || typeof n !== "object") continue;
      out.push(n);
      if (n["@graph"]) walk(n["@graph"]);
      if (n.mainEntity) walk(n.mainEntity);
      if (n.itemListElement) walk(arr(n.itemListElement).map((e: N) => e?.item ?? e));
    }
  };
  $('script[type*="ld+json" i]').each((_, el) => walk(safeJson($(el).text() ?? "")));
  return out;
}

const AVAIL: Record<string, Availability> = {
  instock: "in_stock", limitedavailability: "in_stock", onlineonly: "in_stock", true: "in_stock",
  preorder: "preorder", presale: "preorder", backorder: "preorder",
  outofstock: "out_of_stock", soldout: "out_of_stock", discontinued: "out_of_stock", instoreonly: "out_of_stock",
};
export const mapAvailability = (v: unknown): Availability =>
  AVAIL[String(v ?? "").split("/").pop()!.toLowerCase().replace(/[^a-z]/g, "")] ?? "unknown";

interface OfferRead { price: Money | null; compare_at: Money | null; availability: Availability; url: string | null; sku: string | null; name: string | null }

function readOffers(offers: unknown, deref: (v: any) => any, fallbackCurrency: string | null): OfferRead[] {
  const flat: N[] = [];
  for (const o of arr(offers).map(deref)) {
    if (!o) continue;
    if (is(o, "AggregateOffer") && o.offers) flat.push(...arr(o.offers).map(deref).filter(Boolean));
    else flat.push(o);
  }
  return flat.map((o) => {
    const specs = arr(o.priceSpecification).map(deref).filter(Boolean) as N[];
    const listSpec = specs.find((s) => /StrikethroughPrice|ListPrice|MSRP|SRP/i.test(String(s.priceType ?? "")));
    const saleSpec = specs.find((s) => s !== listSpec && s.price != null);
    const raw = o.price ?? o.lowPrice ?? saleSpec?.price ?? (specs.length === 1 ? specs[0].price : undefined);
    const cur = String(o.priceCurrency ?? saleSpec?.priceCurrency ?? listSpec?.priceCurrency ?? fallbackCurrency ?? "").toUpperCase();
    const hasPrice = (parsePrice(raw, "USD") ?? 0) > 0;          // presence check, currency-agnostic
    const valid = hasPrice && /^[A-Z]{3}$/.test(cur);
    const amount = valid ? parsePrice(raw, cur) : null;
    const price = amount != null && amount > 0 ? { amount, currency: cur } : null;
    const listAmount = price && listSpec ? parsePrice(listSpec.price, cur) : null;
    const compare_at = price && listAmount != null && listAmount > price.amount ? { amount: listAmount, currency: cur } : null;
    return { price, compare_at, availability: mapAvailability(o.availability), url: o.url ?? null,
             sku: o.sku ?? null, name: o.name ?? null, _noCurrency: hasPrice && !valid } as OfferRead;
  });
}

const best = (os: OfferRead[]) =>
  os.filter((o) => o.price).sort((a, b) =>
    (a.availability === "in_stock" ? 0 : 1) - (b.availability === "in_stock" ? 0 : 1) || a.price!.amount - b.price!.amount)[0] ?? null;

export function extractJsonLdProduct(html: string, pageUrl: string, opts: { defaultCurrency: string | null; checkedAt: string; baseUrl: string }) {
  const nodes = parseJsonLdNodes(html);
  if (!nodes.length) return { product: null, miss: "no_jsonld", nodes: 0 } as const;
  const byId = new Map(nodes.filter((n) => typeof n["@id"] === "string").map((n) => [n["@id"] as string, n]));
  const deref = (v: any) => (v && typeof v === "object" && v["@id"] && !v["@type"] && byId.has(v["@id"]) ? byId.get(v["@id"]) : v);
  const canon = (u?: string) => (u ? canonicalizeProductUrl(u, pageUrl) : null);
  const page = canon(pageUrl);
  const metaCurrency = cheerio.load(html)('meta[itemprop="priceCurrency"], meta[property="product:price:currency"]').first().attr("content") ?? null;
  const fallbackCur = metaCurrency?.toUpperCase() ?? opts.defaultCurrency;

  const groups = nodes.filter((n) => is(n, "ProductGroup"));
  const products = nodes.filter((n) => is(n, "Product", "IndividualProduct"));
  if (!groups.length && !products.length) return { product: null, miss: "no_product", nodes: nodes.length } as const;

  let main: N; let variantNodes: N[];
  const group = groups.find((g) => canon(g.url) === page) ?? groups[0];
  if (group) {
    main = group;
    const gid = group.productGroupID;
    variantNodes = [...arr(group.hasVariant).map(deref),
      ...products.filter((p) => deref(p.isVariantOf) === group || (gid && p.inProductGroupWithID === gid))];
    variantNodes = [...new Set(variantNodes)].filter(Boolean);
  } else {
    main = products.find((p) => canon(p.url) === page || arr(p.offers).some((o: N) => canon(deref(o)?.url) === page))
      ?? products.find((p) => p.offers) ?? products[0];
    const key = main.inProductGroupWithID ?? deref(main.isVariantOf)?.["@id"];
    variantNodes = key ? products.filter((p) => p.inProductGroupWithID === key || deref(p.isVariantOf)?.["@id"] === key) : [main];
    if (products.length > 3 && !canon(main.url) && variantNodes.length === 1) {
      // many unrelated products, none matching the page → listing page
      return { product: null, miss: "no_product", nodes: nodes.length } as const;
    }
  }
  const variesBy = arr(group?.variesBy).map((v) => String(v).replace(PREFIX, ""));
  const variants: NormalizedVariant[] = [];
  for (const vn of variantNodes.length ? variantNodes : [main]) {
    const offers = readOffers(vn.offers ?? (vn === main ? undefined : main.offers), deref, fallbackCur);
    const distinct = new Set(offers.map((o) => o.sku ?? o.name).filter(Boolean));
    if (variantNodes.length <= 1 && offers.length >= 2 && distinct.size >= 2) {
      for (const o of offers) if (o.price) variants.push(variantFromOffer(o, main, opts.checkedAt, pageUrl));
      continue;
    }
    const o = best(offers);
    if (!o) continue;
    variants.push(variantFromNode(vn, o, variesBy, opts.checkedAt, pageUrl));
  }
  if (!variants.length) {
    const anyNoCur = variantNodes.concat(main).some((vn) => readOffers(vn.offers, deref, fallbackCur).some((o: any) => o._noCurrency));
    return { product: null, miss: anyNoCur ? "no_currency" : "no_price", nodes: nodes.length } as const;
  }
  const r = finalizeProduct({
    external_id: main.productGroupID ?? main.productID ?? main.sku ?? main.mpn ?? null,
    url: page!, title: decodeEntities(String(main.name ?? "")).trim(),
    description_html: typeof main.description === "string" && /</.test(main.description) ? main.description : null,
    description_text: typeof main.description === "string" ? decodeEntities(main.description) : null,
    brand: typeof main.brand === "string" ? main.brand : deref(main.brand)?.name ?? deref(main.manufacturer)?.name ?? null,
    product_type: null, category: typeof main.category === "string" ? main.category.split(">").pop()!.trim() : null,
    tags: [], images: imagesOf([main, ...variantNodes], deref, pageUrl), options: [],   // options derived in finalize
    variants, source: "jsonld", raw: { nodes: [main, ...variantNodes].slice(0, 50) },
  }, { baseUrl: opts.baseUrl });
  return r.ok ? { product: r.product, miss: null, nodes: nodes.length } : { product: null, miss: "invalid", nodes: nodes.length };
}
declare function variantFromNode(n: N, o: OfferRead, variesBy: string[], checkedAt: string, pageUrl: string): NormalizedVariant;
declare function variantFromOffer(o: OfferRead, main: N, checkedAt: string, pageUrl: string): NormalizedVariant;
declare function imagesOf(ns: N[], deref: (v: any) => any, base: string): { url: string; alt?: string }[];
```

### 5.8 `normalize.ts`

Money and slug parsing live in WS1's isomorphic helpers. Do not re-implement them:
- `parsePrice(raw, currency)` is the lenient scraped-price parser and returns minor units or `null`.
- `toMinor(value, currency)` is strict decimal to minor units.
- `rescaleMinor(amount, fromExp, currency)` rescales from another exponent (Woo).
- `currencyExponent(currency)` gives the currency's minor-unit digits.
- `handleFromUrl(url)` and `slugify(s)` handle slugs.

`normalize.ts` keeps only the crawler-specific parts:

```ts
export function decodeEntities(s: string): string;               // cheerio.load(`<i>${s}</i>`)("i").text()
export function htmlToText(html: string, max = 5000): string;     // strip tags, collapse ws, cut at word boundary
export function finalizeProduct(p: DraftProduct, ctx: { baseUrl: string }):
  { ok: true; product: NormalizedProduct } | { ok: false; reason: string };
export function contentHash(p: NormalizedProduct): string;       // sha256 hex of stable JSON without checked_at/raw
export function modeCurrency(products: NormalizedProduct[]): string | null;
```

**`finalizeProduct(draft)`** is the single gate for every tier's output. It must produce something that passes 00's `NormalizedProductSchema`; WS1's `upsertStoreProducts` re-validates and skips invalid rows.

1. **Title:** decode entities, collapse whitespace, cut to ≤ 300 chars. If it is empty, return `{ok:false, reason:"no_title"}`.
2. **URL and handle:** `url` must be absolute http(s) and canonicalized. `handle` = `draft.handle ?? handleFromUrl(url)`, then `slugify`.
3. **Description:** `description_text` defaults to `htmlToText(description_html)` when absent, and is cut to 5000.
4. **Images:** make them absolute, drop `data:` URLs and placeholders (`/placeholder`, `no-image`, `noimage`), dedupe, keep ≤ 12.
5. **Variants:**
   - Drop a variant when its `offer.price` is missing, not a non-negative integer, or its currency fails `/^[A-Z]{3}$/`. If none remain, return `{ok:false, reason:"no_price"}`.
   - `external_id` may stay `null`. The DB key is `variantKey()` (00 §4.2: source id, then `sku:`, then `opt:`, then `default`, with duplicates suffixed `~2`).
   - Within one product, dedupe variants by `variantKey(v)` from `@/lib/db/upsert-row`; the first one wins.
   - An empty title becomes `Object.values(options).join(" / ") || "Default Title"`.
   - `offer.checked_at` is required; it defaults to now as ISO.
6. **Options:** when `draft.options` is empty, derive them from the union of the variants' option keys, with values in first-seen order. Keep ≤ 10.
7. **Tags:** decode, trim, dedupe, keep ≤ 30.
8. **`raw`:** keep as is. WS1 drops it above 100 KB.

### 5.9 `pipeline.ts`: tier selection

```ts
export interface PipelineInput {
  store: Store;                    // base_url/domain/platform come from here
  maxProducts: number; deadline: number;
  tiers?: ExtractionSource[];      // from CRAWL_TIERS
  preferred?: PreferredStrategy | null;   // from the latest scan (step 0)
}

  method: "api" | "dom";

  recipe?: DomRecipe | null;
  scan_id: string;
}
export interface PipelineHooks {
  log(e: { level: "info" | "warn" | "error"; msg: string; step: CrawlStep; data?: Record<string, unknown> }): void;
  onDetection?(d: DetectionResult, target: StoreTarget): Promise<void> | void;
  onStrategy?(s: StrategyLock): Promise<void> | void;

  stoppedBy: "done" | "max_products" | "time_budget" | "blocked" | "error";
  error: string | null;

  productsEmitted: number; pagesFetched: number; pagesFailed: number;
  currency: string | null; siteName: string | null;
}
export async function runPipeline(input: PipelineInput, hooks: PipelineHooks): Promise<PipelineResult>;
```

**Algorithm.** Follow it literally.

0. **Scan reuse** (DECISIONS A: "indexing uses the best method found").
   - `start.ts` loads `db.getLatestScanForStore(store.id)`. It uses the scan only if its `status` is `done` and `updated_at` is less than 24 h old. It then passes `preferred` as follows:

     | `best_method` | `preferred` |
     |---|---|
     | `api`, with a platform-API signal (`woo_store_api`, `magento_graphql`, `squarespace_json`, `sfcc_product_variation`) or `products_json` | `{method:"api", adapter}`, where `adapter` is the platform, or `shopify` for `products_json` |
     | `api` via UCP/MCP only (a non-Shopify store that already speaks UCP) | `{method:"dom"}`. Indexing through a merchant's MCP is out of scope, so we fall back to T2. Log it. |
     | `dom` | `{method:"dom", recipe: store.dom_recipe}` |
     | `computer_use` or `none` | Not crawled. `startStoreCrawl` throws `AppError("unprocessable", "This store is reachable by computer use only; there is no catalog to index.")` (or `"No agent access method found"` for `none`), unless `force: true`. |

   - With `preferred.method === "api"`, the pipeline **skips fingerprint scoring**. It still does robots, the homepage and the named adapter's own probe, then goes to step 4.
   - With `dom`, it skips step 4 and goes straight to step 5.
   - Without a usable scan, it runs the full detection (steps 1–3).
1. **Setup.**
   - `target = storeTarget(store)`, then `await assertPublicHost(target.origin, flags.allowPrivateStoreHosts())`.
   - `fetcher = createFetcher({ deadline, userAgent: flags.crawlerUserAgent() })`.
2. **Robots.** `robots = await loadRobots(fetcher, target.origin)`. If `robots.blocksUs`, return `status: "blocked"` with `error = "blocked:" + reason`.
3. **Detect.** `d = await detectPlatform(fetcher, target)`.
   - If the homepage was challenged or forbidden, return `blocked`.
   - If it timed out or had a network error, return `failed`.
   - Otherwise call `hooks.onDetection`.
   - Readiness "before" is **not** computed here any more. It comes from the scan (§9).
4. **T0: platform API.** Runs when an adapter is available (`d.adapter` or `preferred.adapter`) and `tiers.includes("platform_api")`.
   - Build the context:
     ```ts
     ctx: CrawlContext = { domain: store.domain, baseUrl: store.base_url, homepageHtml, headers,
                           fetch: fetcher.asFetch(), log: (e) => hooks.log({ ...e, step: "extract" }),
                           signal: AbortSignal.timeout(deadline - Date.now()) }
     ```
   - Pull the **first product** from `adapter.listProducts(ctx, { max: maxProducts })` inside try/catch.
   - On success, lock `{tier:"platform_api", adapter}`, call `hooks.onStrategy`, and keep draining until `max` or the deadline.
   - On `AdapterError` or zero products, log a warn (`"platform API unavailable (<status>); falling back to sitemap+JSON-LD"`) and go to step 5.
   - Magento EDS URL check (UNVERIFIED): GET the first product's `url`. On a 404, switch the adapter to `urlMode: "sitemap"` via `setUrlResolver()`, fed by `discoverProductUrls`.
5. **T2: discover + sample.**
   - Discovery: `disc = await discoverProductUrls(fetcher, target, robots, { platform, hint, max: min(maxProducts * 4, 5000), homepageHtml })`. If there are 0 URLs, fail with `"no_product_urls"`.
   - **Sample** up to 5 URLs at indexes `0, ⌊n/4⌋, ⌊n/2⌋, ⌊3n/4⌋, n−1`.
   - Run the enabled tiers cheapest first:
     1. `jsonld`
     2. `microdata` / `opengraph` (stretch)
     3. `render` (stretch)
     4. `llm` (stretch)
   - When `preferred.recipe` has `title` and `price` selectors and CCR §15.8 is accepted, the `dom_recipe` tier is tried **after** `jsonld`. It reads `$(recipe.title).first().text()` and `parsePrice($(recipe.price).first().text(), storeCurrency)` from the fetched HTML. The currency comes from `modeCurrency` of earlier products, or the store currency.
   - **Lock** the cheapest tier with at least 3 successes. When fewer than 5 URLs exist, the bar is `≥ ceil(0.6 × sample)`.
   - If only some samples succeed, lock the best tier with `partial: true`.
   - If none succeed:
     - 3 or more challenged samples → `blocked`;
     - otherwise `failed` with `"no_structured_data"` and `details` holding the miss counts.
6. **Extract.**
   - Emit the sampled products first, then work through the remaining URLs via the per-host queue.
   - For each URL, **escalate at most one tier**, and never to `llm` unless `llm` is the locked tier.
   - **Circuit breaker:** stop as `blocked` if 5 or more of the first 10 non-sample fetches are challenged.
   - **Handle collision:** a different URL with the same handle gets `handle + "-" + shortHash(url)`.
   - After 3 products, set `defaultCurrency = modeCurrency(emitted)`.
   - **Stop** at `max_products`, at `time_budget` (the deadline), or when the URLs run out (`done`). Pending queue items are cleared.
7. **Result.** `succeeded` when at least 1 product was emitted; otherwise `failed`.

**Constants:**
- Sample size 5, lock minimum 3.
- Discovery budget 25 s.
- `CRAWL_TIME_BUDGET_MS` 240 000.
- `maxProducts` default `flags.crawlMaxProducts()` (150), cap 500.

### 5.10 `run.ts`: `crawlStore` (00 `CrawlStoreFn`)

```ts
export const crawlStore: CrawlStoreFn = async (storeId, crawlRunId, opts = {}) => { /* never throws */ };
```

1. **Load the store.** Use `db.getStoreById(storeId)`. If it is missing, return a synthetic failed `CrawlRun` without writing anything. If it is `opted_out`, fail the run with `"opted_out"`.
2. **Claim the run.** Call `db.claimCrawlRun(crawlRunId)`, which sets `status='running'` and `started_at=now()` where `status='queued'` (§15.3). If it returns `null`, someone else claimed the run; return `db.getCrawlRun(id)`.
3. **Progress writer.** It is throttled and single-flight: at most one write at a time; later writes coalesce.
   - What it writes:
     - `db.updateCrawlRun(id, { products_found, pages_fetched, pages_failed })`
     - `db.appendCrawlLog(id, entries)`
   - When it writes: after 10 or more new products, after 3 s, or on a step change.
   - **Log entries** use 00's `CrawlLogEntry`: `{ at, level, msg, step?, data? }`, with `at` as an ISO timestamp and an optional `step` (`CrawlStep`).
   - WS2 passes entries without `at`; `appendCrawlLog` fills in the current time.
   - `data.total_estimate` = `min(maxProducts, X-WP-Total | Magento total_count | discovered URL count)` on the first `extract` entry.
4. **Persist products.** Buffer products; every 10 and at the end, call `db.upsertStoreProducts(storeId, batch)`, which returns `{upserted, product_ids, skipped}`.
   - `products_found += upserted`. Log each `skipped[]` entry at warn and count it in `pages_failed`.
   - Abort only after 3 batches in a row fail.
5. **Hooks.**
   - `onDetection`: `db.updateStore(id, { platform, metadata: { ...metadata, detection, platform_hint, site_name } })`.
   - `onStrategy`: `db.updateStore(id, { strategy })` and `db.updateCrawlRun(id, { strategy: tierString })`.
6. **Run the pipeline** inside try/catch. Any throw becomes `failed` with `String(err).slice(0, 500)`.
7. **Finalize** (in `finally`):
   - Flush the product buffer and the progress writer.
   - `stats = await db.getIndexStats(storeId)` (B12; shape requested in §15.3).
   - **Checkout connector:** `resolveCheckoutConnector({ domain: store.domain, platform })`, imported from `@/lib/checkout/connectors` (WS4, B10). Also write the legacy `checkout_methods = [connector]` if `StorePatch` supports it.
   - **Store update:** `db.updateStore(id, { status, platform, currency, name: store.name ?? siteName, strategy, checkout_connector, last_crawled_at: now, metadata })`. `status` is:
     - `blocked` for a blocked result, with `metadata.block_reason`;
     - otherwise `indexed` when `stats.product_count > 0`, even after a failed re-crawl;
     - otherwise `failed`.
   - **After report:** `after = await computeReadiness(freshStore, "after")`, then `db.setStoreReadiness(id, "after", after)`.
   - **Scan update:** if the store has a `latest_scan_id`, `db.upsertScan({ id, after: { score, grade } })` records the **actual** after score (DECISIONS: "projected / actual via ShoperZero"). The score comes from `score.ts` `afterScore()` (§6.8).
   - **Run update:** `db.updateCrawlRun(id, { status: result.status === "succeeded" ? "succeeded" : "failed", error, finished_at: now })`.
   - Return `db.getCrawlRun(id)`.
8. **Idempotency.**
   - Upserts use `(store_id, url)` for products and `(product_id, variantKey)` for variants. Missing variants are marked `available=false`, never deleted (WS1).
   - `content_hash` lets WS1 skip unchanged writes.

### 5.11 `start.ts`: `startStoreCrawl`

```ts
export async function startStoreCrawl(rawUrl: string, opts: { maxProducts?: number; force?: boolean; storeId?: string } = {})
```

1. **Resolve the store.**
   - `opts.storeId` → `db.getStoreById`; missing → `AppError("not_found")`.
   - Otherwise `normalizeStoreUrl(rawUrl, { allowPrivate })` (an error → `validation_error`), then `assertPublicHost`, then `db.upsertStoreForUrl(rawUrl)`.
2. **Opt-out.** `store.opted_out` → `AppError("forbidden", "The merchant has opted out of ShoperZero.")`.
3. **Active run.** If there is one (`db.getActiveCrawlRun(store.id, 6)`, queued or running, under 6 min old), return it with `{reused: true, cached: true}`. This holds **even with `force`**.
4. **Recent result.** Without `force`, if the store is `indexed` and was last crawled under 6 h ago, return `db.getLatestCrawlRun` with `{reused: false, cached: true}` (WS5 CCR-3). A store that is `blocked` and was last crawled under 6 h ago gets the same cached response, and the caller reads `store.status`.
5. **Scan gate.** Apply §5.9 step 0. A `computer_use` or `none` best method without `force` throws `AppError("unprocessable", …)`.
6. **Concurrency.** If `db.countActiveCrawlRuns(6) >= CRAWL_MAX_CONCURRENT_RUNS`, throw `AppError("rate_limited", "Too many crawls running; retry in 30 s.")`.
7. **Start.**
   - `run = await db.createCrawlRun(store.id)`, then `db.updateStore(store.id, { status: "crawling" })`.
   - Schedule the crawl:
     ```ts
     after(async () => { await crawlStore(store.id, run.id, { maxProducts }); })
     ```
     `crawlStore` never throws.
   - Return `{ store: (await db.getStoreById(store.id))!, crawl_run: run, reused: false, cached: false }`.

### 5.12 `verify.ts`: `verifyOffer` (00 `VerifyOfferFn`, 8 s)

1. **Load** with `db.getVariantForVerify(variantId)` (§15.3): the variant, its product (`url`, `external_id`, `handle`) and its store.
   - Missing → `OfferVerificationError` with reason `variant_not_found` (`AppError` code `not_found`).
   - `opted_out` → reason `opted_out` (code `forbidden`).
   - Build `previous` from the DB row.
2. **Cache.** Keep a module-level `Map<variantId, {offer, at}>`. Return `source: "cache"` when the cached entry, or `previous.checked_at`, is within `maxAgeMs` (default 60 000).
3. **Live fetch.**
   - Create a fetcher with `deadline = now + 8000`, and load robots (cached per host for 10 min).
   - If `store.strategy.tier === "platform_api"` and the adapter has `fetchOffer`, call `adapters[adapter].fetchOffer(ctx, { url, external_id }, variant.external_id)`. The context has `homepageHtml: ""`, empty `headers`, a no-op `log` and an 8 s `signal`.
   - Otherwise GET `variant.url ?? product.url` and run the locked tier's extractor.
   - **Match the variant** in this order: equal `variantKey`, then equal `sku`, then deep-equal `options`, then "exactly one variant". If none match, the reason is `variant_gone`.
4. **Errors.** Every `OfferVerificationError` carries `lastKnown: previous`.

   | Condition | Reason | `AppError` code |
   |---|---|---|
   | HTTP 404 or 410 | `product_gone` | `upstream_error` |
   | Challenge, robots or 403 | `blocked` | `upstream_blocked` |
   | Timeout | `unreachable` | `upstream_timeout` |
   | Network error | `unreachable` | `upstream_error` |
   | No price parsed | `no_price` | `upstream_error` |

5. **Persist.** `db.updateVariantOffer(variantId, offer)`, which also recomputes the parent's range and availability. `changed.price` is true when the amount or currency differs; `changed.availability` likewise.
6. **Budget.** One retry on a network error, within a hard 8 s total.

WS4 guidance (a recommendation, not enforced here):
- If this throws `blocked` or `unreachable`, or the availability is not `in_stock`, go to the handoff path.
- If `changed.price`, quote the new price and add an info message.

## 6. Scan & score (`src/lib/scan/**`)

The entry experience (DECISIONS A):
1. A visitor pastes a URL.
2. A discovery agent tries `api`, then `dom`, then `computer_use`, **stopping at the first method that passes**.
3. We report an **Agent Readiness Score**, with per-method seconds and USD per agent task.
4. We offer "Make it agent-ready", which runs indexing (§5).

Types come from `@/lib/contracts` (`scan.ts`, owned by WS1): `AccessMethod`, `ProbeStatus`, `Capabilities`, `ProbeSignal`, `DomRecipe`, `AccessProbe`, `ScanMode`, `ScanStatus`, `ScanReport`. Their names are used exactly.

### 6.1 Definitions

**Agent task** (the unit for `est_seconds_per_task` / `est_usd_per_task`): starting from the store homepage, find one product, read its price and availability, add it to the cart, and reach the checkout page. Payment is not part of the task.

**Capabilities.** Each one is a boolean, true only if **this probe** demonstrated it:

| Capability | True when |
|---|---|
| `catalog` | The method can enumerate products: ≥ 3 distinct products listed via API, sitemap, listing page or search. |
| `product_detail` | It can open one product and read its title (plus description or images). |
| `price_availability` | For ≥ 1 product, it can read a price **with currency** and an availability that is not `unknown`. A visible, enabled add-to-cart counts as in stock. |
| `variants` | Options or variants are exposed for ≥ 1 product: more than one variant, a ProductGroup, a configurable product, or a working variant picker. |
| `cart` | An item was actually added to a cart: an API cart endpoint confirmed read-only, or a DOM or computer-use add-to-cart that increased the cart. |
| `checkout_reachable` | The checkout page or endpoint was reached. We **never** submit it. |

**Probe status:**

| Status | Rule |
|---|---|
| `passed` | `catalog && price_availability` (DECISIONS: "an agent could at least list products with price and availability") |
| `partial` | At least one capability is true, but the probe did not pass |
| `failed` | No capability |
| `blocked` | Robots, Content-Signal, a bot challenge, or 403 prevented probing, and no capability was shown |
| `skipped` | Not tried (the cascade stopped earlier, the method is disabled, or no browser or API key is available); `error.code` says why |

**Cascade.** In `mode: "cascade"` (the default), stop at the first `passed` probe. `partial`, `failed` and `blocked` all continue to the next method. Probes that are not run end as `skipped`. `mode: "full"` (stretch) runs all three.

**`best_method`:** the first `passed` method in cascade order. If none passed, the first `partial` one. Otherwise `"none"`.

**Estimates** (`estimate.ts`):
- `est_seconds_per_task` = `round1(3 × median(latency of the ok requests) / 1000)`. That is one catalog call, one detail call and one cart call; typically about 1 s.
- `est_usd_per_task` = `0.00`. There is no browser or model cost on our side. The agent's own reasoning tokens are excluded, and the report page footnotes this.

### 6.4 `browser.ts`: where browser probes run

Both `dom` verification and `computer_use` need a real Chromium.

| Environment | Browser | Notes |
|---|---|---|
| Vercel (prod/preview) | **Browserbase** via CDP (required) | Chromium can't practically run inside a Vercel function (bundle size, cold start). The function only orchestrates. The `after()` of `POST /api/v1/scans` has `maxDuration = 300`, which is the Hobby maximum. |
| Local `next dev` / scripts | Browserbase if keys are set, else local Chromium through `playwright-core` | Run `npx playwright install chromium` once (dev dependency `playwright`) |
| Neither available | none | `dom` stage C is replaced by HTTP-only verification (§6.5). `computer_use` becomes `skipped` with `error.code = "no_browser"`. |

```ts
// src/lib/scan/browser.ts
import { chromium, type Page, type BrowserContext } from "playwright-core";
import Browserbase from "@browserbasehq/sdk";

export interface BrowserHandle {
  page: Page; context: BrowserContext; provider: "browserbase" | "local";
  costUsdPerMinute: number;            // browserbase 0.002 (Developer overage $0.12/h, research 07); local 0
  close(): Promise<void>;
}
export const VIEWPORT = { width: 1280, height: 800 };   // 46×29 = 1,334 visual tokens per screenshot (⌈w/28⌉×⌈h/28⌉)

export async function openBrowser(opts: { target: StoreTarget; robots: RobotsInfo; blockHeavy?: boolean }): Promise<BrowserHandle | null> {
  const apiKey = optionalEnv("BROWSERBASE_API_KEY"), projectId = optionalEnv("BROWSERBASE_PROJECT_ID");
  let browser;
  let provider: BrowserHandle["provider"];
  if (apiKey && projectId) {
    const bb = new Browserbase({ apiKey });
    // UNVERIFIED field names: check the @browserbasehq/sdk README. Captcha solving MUST be off (we never bypass bot walls).
    const session = await bb.sessions.create({ projectId, browserSettings: { solveCaptchas: false, viewport: VIEWPORT } });
    browser = await chromium.connectOverCDP(session.connectUrl);
    provider = "browserbase";
  } else if (!process.env.VERCEL) {
    browser = await chromium.launch({ headless: true });
    provider = "local";
  } else return null;
  const context = browser.contexts()[0] ?? await browser.newContext();
  const page = context.pages()[0] ?? await context.newPage();
  await page.setViewportSize(VIEWPORT);
  // Honest identification: a normal Chromium UA plus our token (the Browserbase UA can't always be overridden; then the header below still identifies us).
  await context.setExtraHTTPHeaders({ "X-ShoperZero-Scan": `ShoperZeroBot/0.1 (+${appUrl()}/bot)` });
  await installGuards(page, opts);     // navigation + robots + SSRF guard, see below
  return { page, context, provider, costUsdPerMinute: provider === "browserbase" ? 0.002 : 0,
           close: async () => { await browser.close().catch(() => {}); } };
}
```

**`installGuards(page)`** (in `guard.ts`):
- **Robots and SSRF.** `page.route("**/*")` aborts main-frame document requests whose URL fails `robots.isAllowed(url)` or `assertPublicHost`. With `blockHeavy`, it also aborts `image`, `media` and `font` requests; the DOM verification uses this, computer use does not.
- **Same site only.** On main-frame navigation (`framenavigated`), the host must match the store's registrable domain (www-insensitive) or a hosted-checkout host allowlist:
  - `checkout.shopify.com`, `*.myshopify.com`
  - `*.bigcommerce.com`
  - `secure.squarespace.com`, `*.squarespace.com`
  - `*.demandware.net`

  Otherwise go back and record the attempt as an error.
- **Challenges.** After each navigation, run `detectChallenge(200, headers, await page.content())`. A challenge ends the probe as `blocked`.

### 6.5 `probes/dom.ts`: scraping plus the DOM agent

The budget is **70 s** in three stages: A 20 s, B 20 s, C 30 s.

**Stage A: structured data over HTTP.** No browser and no model.
- Reuse `ctx.shared.discovery` and `ctx.shared.pdpSample` (3 product pages from `checks.ts`, §6.7). If they are absent, run `discoverProductUrls` (max 50) and fetch 3 product pages.
- Run `extractJsonLdProduct`, plus `extractMicrodataOrOg` when T3 is enabled.
- Signals:
  - `sitemap_products`: "`n` product URLs"
  - `jsonld_product`: "`k`/3 pages"
  - `jsonld_offer`: price + currency + availability
  - `jsonld_variants`
- Capabilities:
  - `catalog` = `discovery.urls.length ≥ 3 && k ≥ 1`
  - `product_detail` = `k ≥ 1`
  - `price_availability` = some sampled offer has a price and an availability that is not `unknown`
  - `variants` = some product has more than 1 variant
- `sample_products = k`.

**Stage B: the DOM agent builds a `DomRecipe`.**

*Recommendation.* Build the recipe with **cheerio + Claude on fetched HTML**, then verify it in a real browser with **plain Playwright** (Stage C). Stagehand is the fallback for repairing a selector (stretch).

| Option | Pros | Cons | Verdict |
|---|---|---|---|
| **cheerio + Claude on fetched HTML** | No browser needed to build the recipe, so it works on Vercel even without Browserbase. One model call. Deterministic validation (`$(sel).length`). Cheap: ~4 pages × ~3k tokens. | Misses DOM that only exists after JS runs | **Primary** |
| Stagehand `observe`/`extract`/`act` (v3+: `stagehand.observe(instruction)` returns `[{selector, description, method, arguments}]`; `stagehand.act(observeResult)`; `stagehand.extract({instruction, schema})`; `stagehand.context.pages()[0]`) | Works on the live, rendered DOM and returns XPath selectors ready to act on | A browser session per scan (Browserbase minutes). The v4.1 API is **UNVERIFIED** (research 07 warns about the v3→v4 changes). An extra dependency and a model-config surface (Stagehand's own `model` string). Slower, with several LLM calls. | **Fallback / stretch:** when Stage C finds that a recipe selector matches nothing on the rendered page, call `stagehand.observe("find the <role>")` on that page and replace the selector with the returned `selector` |
| Claude `browser_toolset_20260801` | Anthropic's browser-use toolset reads and acts on the page | It is an agent loop, much like computer use, with no stable selectors as output. Member tools are unverified for us. | Not for the recipe |

*Steps:*

1. **Pages** (fetched with the scan fetcher, via HTTP):
   - `home`: already fetched.
   - `listing`: the first homepage link whose path matches `/(shop|store|collections?|category|categories|products?)(\/|$)/i`, else `/shop`, `/collections/all`, `/products`, keeping the first that returns 200 HTML.
   - `pdp`: `pdpSample[0].url`, else the first homepage or listing link with `productUrlScore > 0`.
   - `cart`: the first 200 HTML among `/cart`, `/cart.php`, `/basket`, `/checkout/cart`, `/bag`.
2. **Outline each page** with cheerio.
   - Drop `script`, `style`, `svg`, `noscript`, `iframe`, `template` and the `head` (keep `<title>`).
   - Keep these elements:
     - `a`, `button`, `input`, `select`, `option` (the first 5 per select), `form`, `label`;
     - `[role]`, `[itemprop]`, `h1`–`h3`;
     - any element whose `id`/`class`/`name`/`data-*` matches `/price|cart|basket|bag|search|product|variant|option|swatch|size|colou?r|add|buy|checkout|qty|quantity/i`.
   - Emit one line per element: indentation for depth (≤ 8), then `tag#id.cls1.cls2[name=][type=][href=][action=][aria-label=][data-*=] "text≤60"`.
   - Collapse repeated siblings with the same signature to the first 3, then `… ×N`.
   - Cap each page at 12 000 chars.
3. **One model call.** `SCAN_MODEL` defaults to `claude-opus-5-5`, with low effort because this is an extraction task. The request uses structured output plus server-side refusal fallbacks:

```ts
// src/lib/scan/probes/dom.ts (recipe stage)
import Anthropic from "@anthropic-ai/sdk";
import { z } from "zod";

const RecipeSchema = z.object({
  search_input: z.string().nullable(), product_card: z.string().nullable(), product_link: z.string().nullable(),
  title: z.string().nullable(), price: z.string().nullable(), variant_picker: z.string().nullable(),
  add_to_cart: z.string().nullable(), cart_link: z.string().nullable(), checkout_link: z.string().nullable(),
  notes: z.string().describe("One or two sentences on anything unusual, e.g. 'add to cart is an AJAX drawer'."),
});
const SYSTEM = `You map an online store's page structure for an AI shopping agent.
You get compact outlines of the home, listing, product and cart pages. Return one CSS selector per field.
Prefer stable selectors: #id, [name=], [data-*], [aria-label], [itemprop], form[action*=], href patterns.
Avoid :nth-child and generated class names (random hashes). product_link must match anchors that open product
pages from the home or listing page; product_card the repeating card element; title and price are on the product
page; variant_picker the size/colour control; add_to_cart the product page's add button or submit; cart_link the
header cart/bag link; checkout_link the cart page's proceed-to-checkout link. Use null when absent.
Never return selectors for payment, login or personal-data fields.`;

export async function buildRecipe(outlines: { page: "home" | "listing" | "pdp" | "cart"; url: string; outline: string }[]) {
  const client = new Anthropic();                              // ANTHROPIC_API_KEY (requireEnv → not_implemented)
  const res = await client.beta.messages.create({
    model: optionalEnv("SCAN_MODEL") ?? "claude-opus-5-5",
    max_tokens: 4000,
    betas: ["server-side-fallback-2026-07-01"],
    fallbacks: "default",                                      // refusal → server-side fallback model
    output_config: { effort: "low", format: { type: "json_schema", schema: z.toJSONSchema(RecipeSchema, { io: "input" }) } },
    system: SYSTEM,
    messages: [{ role: "user", content: outlines.map((o) => `### ${o.page} (${o.url})\n${o.outline}`).join("\n\n") }],
  });
  if (res.stop_reason === "refusal" || res.stop_reason === "max_tokens") return { recipe: null, usage: res.usage, error: res.stop_reason };
  const text = res.content.find((b) => b.type === "text")?.text ?? "";
  const parsed = RecipeSchema.safeParse(JSON.parse(text));
  return { recipe: parsed.success ? parsed.data : null, usage: res.usage, error: parsed.success ? null : "invalid_json" };
}
```

   - If the SDK or API rejects combining `fallbacks` with `output_config.format` (UNVERIFIED), drop `betas`/`fallbacks` and call `client.messages.parse({ …, output_config: { effort: "low", format: zodOutputFormat(RecipeSchema) } })`, reading `parsed_output` (null means the parse failed).
   - If `z.toJSONSchema` output is rejected, hand-write the JSON Schema. Every field is required and nullable, and `additionalProperties: false` is set.
4. **Validate each selector with cheerio** against the page it belongs to:
   - `product_card` and `product_link` → listing or home
   - `title`, `price`, `variant_picker`, `add_to_cart` → pdp
   - `cart_link` → home
   - `checkout_link` → cart
   - `search_input` → home

   A selector that throws, or matches 0 elements, becomes `undefined`. `price` must match text that `parsePrice(text, currency)` can parse. Any selector matching `PAYMENT_FIELD_RE` (§6.6 guard) is dropped. The result is `DomRecipe` with `notes`, and no `verified_at` yet.
5. **Signals:** `recipe_built` ("k/9 selectors valid"), plus `recipe_product_link`, `recipe_add_to_cart` and `recipe_cart_link`.

**Stage C: verify the recipe by following it** (browser, 30 s, **stop before payment**). Use `openBrowser({ blockHeavy: true })`. Each step has an 8 s timeout, and every click goes through `guard.checkClick` (§6.6).

1. `page.goto(home)`. If `search_input` is set: type the first word of a sampled product title and press Enter. `search_verified` is true if `product_link` then matches at least 1 element.
2. Navigate via `product_link`: go to the listing if needed, click the first visible match, then `waitForURL(u => u !== before)`. Read `title` and `price` there. This gives `product_detail` and `price_availability`, with an enabled `add_to_cart` counting as in stock.
3. If there is a `variant_picker`: a `<select>` gets its first non-disabled, non-empty option; a swatch or radio group gets its first enabled element clicked. This gives `variants`.
4. Record the cart count first: read the header count text inside `cart_link` (`/\d+/`), else 0. Click `add_to_cart`, then wait for networkidle, max 5 s.
5. Navigate via `cart_link` (click it, or `goto` its href). `cart` = the cart page lists the product title, or the count has increased.
6. Take the `checkout_link` href from the cart page. **Do not click submit buttons.** `page.goto(href)`. `checkout_reachable` = status < 400 and (the URL matches `CHECKOUT_URL_RE` or an email/address input is present). **Stop here.** Fill nothing. The session closes, and the cart is abandoned with no order.
7. If steps 2–6 all passed, `recipe.verified_at = now`. A partial verification keeps the verified capabilities.

**Without a browser** (on Vercel with no Browserbase keys), use HTTP-only verification:
- `product_link` href → 200 PDP whose `title` selector matches;
- `checkout_link` href → 200.
- `cart` stays false and the signal detail reads "add to cart not browser-verified".

**Result and cost.**
- `status` follows §6.1, using the union of the stage A and C capabilities.
- `recipe` is always attached when it was built.
- `sample_products` = the stage A count, or 1 if only stage C found a product.
- **Estimates:**
  - `est_seconds_per_task` = the measured stage C duration. Without a browser: `4 pages × median page latency + 2 s`.
  - `est_usd_per_task` = `4 pages × 3,000 input tokens × price_in(model)` + `seconds/60 × costUsdPerMinute`. With `claude-opus-5-5` that is ≈ $0.06, plus pennies of browser time.

**Persistence.** After the scan:
- `stores.dom_recipe` = the recipe, **only if** `verified_at` is set, or if it passed HTTP-only verification of `product_link` + `title` + `price`.
- WS4's stretch `browser` connector reads `stores.dom_recipe`.

### 6.6 `probes/computer-use.ts`: Claude computer use on a real browser

This file depends only on `ProbeContext`, `browser.ts`, `guard.ts`, `estimate.ts` and the db upload helper, so a third person can own it.

**Preconditions**, each checked in order; a failure makes the probe `skipped` with this `error.code`:

| Check | `error.code` if missing |
|---|---|
| `SCAN_CU_ENABLED !== "0"` | `disabled` |
| `ANTHROPIC_API_KEY` is set | `not_implemented` |
| `openBrowser()` returns a browser (not `null`) | `no_browser` |
| ≥ 40 s remain before the scan deadline | `time_budget` |

**Budget:** 150 s wall clock. **`SCAN_CU_MAX_STEPS`** (default 15) model turns. A turn may batch several actions, capped at 40 actions in total.

**Model and tool** (Claude API, current as of 2026-09-26):
- Model `claude-opus-5-5` (`SCAN_MODEL`).
- Tool entry `{ type: "computer_toolset_20260801", configs: { … } }`. It is GA and needs **no beta header**; it takes **no `name`** and **no display size**. Unneeded members are disabled to save tokens: `zoom`, `hold_key`, `left_mouse_down`, `left_mouse_up`, `middle_click`, `triple_click`, `cursor_position`.
- Claude calls the tool with `tool_use` blocks whose `name` is the member (`screenshot`, `left_click`, `double_click`, `right_click`, `left_click_drag`, `mouse_move`, `scroll`, `type`, `key`, `wait`) and which carry `toolset_name: "computer"`. Several may arrive per turn. **Every `tool_result` must echo `"toolset_name": "computer"`.**
- Coordinates are screenshot pixels. The viewport is 1280×800 with `deviceScaleFactor` 1, so no scaling is needed (limit: long edge ≤ 2576 px, ≤ 4,784 visual tokens).
- The older `computer_20251124` form with beta `computer-use-2025-11-24` is **not** used. It can't share a request with the toolset.
- If the pinned SDK (0.128) typings lack the toolset types, cast the tool entry and the result blocks (`as unknown as Anthropic.Beta.BetaToolUnion`). The wire shape above is authoritative.
- Thinking is adaptive and on by default on Opus 5. Set `thinking: { type: "adaptive", display: "summarized" }` so each step has readable reasoning, and `output_config: { effort: "medium" }`.
- A custom tool **`report_result`** (with `strict: true`) lets the model finish with facts:
  ```ts
  { reached: "home" | "product" | "cart" | "checkout",
    product_title: string | null, price_text: string | null, availability_text: string | null,
    variant_selected: boolean, notes: string }
  ```

**Task prompt** (the user turn, with the first screenshot):
> You are testing whether an AI shopping assistant could use this store: {base_url}. Starting from the homepage shown, find any product, open it, note its price and availability, choose a variant if one is required, add one unit to the cart, open the cart, and go to the checkout page. STOP as soon as the checkout page is visible — never enter personal details, never log in, never enter payment information, never place an order. If a login wall, CAPTCHA or error blocks you, stop. Call report_result when done or stuck.

**System prompt:** "You operate a web browser to evaluate e-commerce stores for agent readiness. Use as few steps as possible. Prefer clicking visible links and buttons over typing URLs. Payment and account actions are forbidden."

**Stop-before-payment guard** (`guard.ts`, shared with the `dom` probe):

```ts
export const PAY_RE = /\b(place (your )?order|pay( now)?|complete (order|purchase|payment)|confirm (order|purchase|and pay)|submit order|buy now|purchase now|express checkout|pay with|apple pay|google pay|paypal|shop pay|klarna|afterpay)\b/i;
export const PAYMENT_IFRAME_RE = /stripe|braintree|adyen|paypal|klarna|afterpay|checkout\.com|squareup|authorize\.net|shopifycs|pay\.shopify/i;
export const PAYMENT_FIELD_RE = /card|cc-?(num|number|exp|csc)|cvc|cvv|expir|iban|account.?number|password|passwd/i;
export const CHECKOUT_URL_RE = /\/(checkout|checkouts|order-pay|payment|onepage)(\/|\?|$)|checkout\.shopify\.com|action=checkout/i;

/** Before any click: inspect the element under the point. */
export async function checkClick(page: Page, x: number, y: number): Promise<{ block: false } | { block: true; reason: string }> {
  const el = await page.evaluate(([px, py]) => {
    const e = document.elementFromPoint(px, py);
    const t = e?.closest("button,a,input,[role=button],label,summary") as HTMLElement | null;
    return e && { tag: e.tagName, iframeSrc: e.tagName === "IFRAME" ? (e as HTMLIFrameElement).src : null,
      text: (t?.innerText || (t as HTMLInputElement | null)?.value || "").slice(0, 120),
      aria: t?.getAttribute("aria-label") ?? "", href: t?.getAttribute("href") ?? "",
      name: t?.getAttribute("name") ?? "", autocomplete: t?.getAttribute("autocomplete") ?? "" };
  }, [x, y] as const);
  if (!el) return { block: false };
  if (el.iframeSrc && PAYMENT_IFRAME_RE.test(el.iframeSrc)) return { block: true, reason: "payment_iframe" };
  if (PAY_RE.test(`${el.text} ${el.aria}`)) return { block: true, reason: "payment_button" };
  if (/^cc-/.test(el.autocomplete) || PAYMENT_FIELD_RE.test(el.name)) return { block: true, reason: "payment_field" };
  return { block: false };
}
/** Before `type`: the focused element must not be a payment/credential field (incl. focus inside a payment iframe). */
export async function checkType(page: Page): Promise<{ block: false } | { block: true; reason: string }>;
```

- **Blocked actions** are not executed. Their `tool_result` is `is_error: true` with the content "ShoperZero stop rule: this action would start payment or enter payment or account details. Do not retry. Call report_result now."
- The guard **ends the loop** (`stop = "payment_guard"`). A `payment_button` block on a checkout page counts as `checkout_reachable`.
- **URL rule:** after every action, if `CHECKOUT_URL_RE.test(page.url())`, take a final screenshot and end with `stop = "checkout_reached"`. The model never gets a turn on the checkout page, so it cannot fill forms.

**Executing members with Playwright** (`execute(page, call)`):

| Member | Playwright action |
|---|---|
| `screenshot` | `page.screenshot({ type: "jpeg", quality: 70 })` → `[{ type: "image", source: { type: "base64", media_type: "image/jpeg", data } }]` |
| `left_click`, `right_click`, `double_click` | `checkClick`, then `page.mouse.click(x, y, { button, clickCount })`. Modifier keys in `text` are held with `keyboard.down/up`. |
| `left_click_drag` | `mouse.move(start)`, `down()`, `move(coordinate, { steps: 10 })`, `up()` |
| `mouse_move` | `page.mouse.move(x, y)` |
| `scroll` | `mouse.move(coordinate)` if given, then `page.mouse.wheel(dx, dy)` with 100 px per `scroll_amount` in `scroll_direction` |
| `type` | `checkType`, then `page.keyboard.type(text, { delay: 15 })` |
| `key` | Map xdotool names to Playwright (`Return`→`Enter`, `BackSpace`→`Backspace`, `Page_Down`→`PageDown`, `ctrl`→`Control`, `super`→`Meta`, `alt`→`Alt`), then `keyboard.press(mapped)` × `repeat` (≤ 10) |
| `wait` | Sleep `min(duration, 5)` s |

After each non-screenshot action, run `page.waitForLoadState("domcontentloaded", { timeout: 3000 }).catch(() => {})` and wait 300 ms. The result is `"OK"`.

**Batch rules:**
- Run the calls of a turn **sequentially**.
- After the first failure, every remaining call gets `"Not executed: an earlier computer action in this turn failed."`.

**Loop sketch:**

```ts
// src/lib/scan/probes/computer-use.ts
import Anthropic from "@anthropic-ai/sdk";

const COMPUTER = { type: "computer_toolset_20260801", configs: {
  zoom: { enabled: false }, hold_key: { enabled: false }, left_mouse_down: { enabled: false },
  left_mouse_up: { enabled: false }, middle_click: { enabled: false }, triple_click: { enabled: false },
  cursor_position: { enabled: false } } } as unknown as Anthropic.Beta.BetaToolUnion;
const REPORT: Anthropic.Beta.BetaTool = { name: "report_result", strict: true, description: "Finish the test and report what was reached.",
  input_schema: { type: "object", additionalProperties: false,
    required: ["reached", "product_title", "price_text", "availability_text", "variant_selected", "notes"],
    properties: { reached: { type: "string", enum: ["home", "product", "cart", "checkout"] },
      product_title: { type: ["string", "null"] }, price_text: { type: ["string", "null"] },
      availability_text: { type: ["string", "null"] }, variant_selected: { type: "boolean" }, notes: { type: "string" } } } };

export const computerUseProbe: ProbeFn = async (ctx) => {
  const probe = { ...emptyProbe("computer_use", "running"), started_at: iso(), screenshots: [] as string[], steps: [] as NonNullable<AccessProbe["steps"]> };
  const b = await openBrowser({ target: ctx.target, robots: ctx.robots });
  if (!b) return { ...probe, status: "skipped", error: { code: "no_browser", message: "No browser available (set BROWSERBASE_API_KEY/PROJECT_ID)." } };
  const client = new Anthropic();
  const usage = new UsageMeter("claude-opus-5-5");                      // estimate.ts
  const t0 = Date.now();
  let stop: string | null = null;
  let report: ReportResult | null = null;
  let actions = 0;
  try {
    await b.page.goto(ctx.store.base_url, { waitUntil: "domcontentloaded", timeout: 15_000 });
    if (await isChallenged(b.page)) return finish("blocked");
    const first = await shoot(b.page, ctx, probe, 0, "Open homepage");    // uploads + pushes screenshot + ctx.update()
    const messages: Anthropic.Beta.BetaMessageParam[] = [{ role: "user", content: [{ type: "text", text: taskPrompt(ctx) }, first.block] }];

    for (let turn = 1; turn <= maxSteps(); turn++) {
      if (Date.now() > ctx.deadline - 8_000) { stop = "time_budget"; break; }
      const res = await client.beta.messages.create({
        model: scanModel(), max_tokens: 4096,
        betas: ["server-side-fallback-2026-07-01"], fallbacks: "default",   // see note below
        thinking: { type: "adaptive", display: "summarized" }, output_config: { effort: "medium" },
        cache_control: { type: "ephemeral" },                              // top-level auto prompt caching
        system: SYSTEM, tools: [COMPUTER, REPORT], messages,
      }, { signal: ctx.signal });
      usage.add(res.usage);
      messages.push({ role: "assistant", content: res.content });          // append-only: keep thinking blocks unchanged
      if (res.stop_reason === "refusal") { stop = "refusal"; break; }
      const calls = res.content.filter((c): c is Anthropic.Beta.BetaToolUseBlock => c.type === "tool_use");
      if (calls.length === 0) { stop = "model_done"; break; }
      const results: Anthropic.Beta.BetaToolResultBlockParam[] = [];
      let halted = false;
      for (const call of calls) {
        if (call.name === "report_result") { report = call.input as ReportResult; results.push({ type: "tool_result", tool_use_id: call.id, content: "OK" }); stop = "reported"; continue; }
        const base = { type: "tool_result" as const, tool_use_id: call.id, toolset_name: "computer" };
        if (halted || ++actions > 40) { results.push({ ...base, content: "Not executed: an earlier computer action in this turn failed." } as never); continue; }
        const g = await guardFor(b.page, call);                            // checkClick / checkType by member
        if (g.block) { results.push({ ...base, is_error: true, content: STOP_RULE_MSG } as never); stop = "payment_guard"; halted = true; continue; }
        try { results.push({ ...base, content: await execute(b.page, call) } as never); }
        catch (e) { halted = true; results.push({ ...base, is_error: true, content: String((e as Error).message).slice(0, 300) } as never); }
      }
      messages.push({ role: "user", content: results });
      await shoot(b.page, ctx, probe, turn, summarize(calls), reasoningOf(res));   // step i=turn, screenshot for the UI
      if (CHECKOUT_URL_RE.test(b.page.url())) { stop = "checkout_reached"; break; }
      if (stop) break;
    }
    return finish(null);
  } catch (e) {
    return finish(null, { code: "cu_error", message: String((e as Error).message).slice(0, 300) });
  } finally { await b.close(); }

  function finish(forced: ProbeStatus | null, error?: { code: string; message: string }): AccessProbe {
    const caps = capabilitiesFrom({ report, stop, url: b!.page.url(), currency: ctx.store.currency });
    const seconds = (Date.now() - t0) / 1000;
    return { ...probe, capabilities: caps, status: forced ?? statusFrom(caps),
      finished_at: iso(), duration_ms: Date.now() - t0, sample_products: caps.product_detail ? 1 : 0,
      est_seconds_per_task: Math.round(seconds), est_usd_per_task: usage.usd() + (seconds / 60) * b!.costUsdPerMinute,
      signals: [...probe.signals, { id: "cu_stop", label: "Stopped because", ok: stop === "checkout_reached" || stop === "payment_guard" || stop === "reported", detail: stop ?? "error" }],
      ...(error ? { error } : {}) };
  }
};
```

- `fallbacks: "default"` retries a refused turn on Anthropic's recommended fallback model.
- **UNVERIFIED:** whether every fallback target accepts the computer toolset. If a fallback turn errors on the tool type, drop `betas`/`fallbacks` for computer use and treat a `refusal` as `stop = "refusal"`.

**Capabilities from computer use** (`capabilitiesFrom`):

| Capability | True when |
|---|---|
| `catalog` | `report.reached` is `product`, `cart` or `checkout` (the model found a product from the home or listing page) |
| `product_detail` | `report.product_title` is non-empty |
| `price_availability` | `parsePrice(report.price_text, currency ?? "USD") != null` and (`availability_text` is non-empty, or `reached` is `cart` or `checkout`) |
| `variants` | `report.variant_selected` |
| `cart` | `reached` is `cart` or `checkout`, or stop is `checkout_reached` |
| `checkout_reachable` | stop is `checkout_reached`, stop is `payment_guard` on a checkout URL, or `reached === "checkout"` |

The status comes from §6.1.

**Screenshots and progress (Realtime):**
- `shoot()` takes a JPEG (quality 70, viewport) and **uploads** it to the Storage bucket **`scan-screenshots`** at `{scan_id}/cu-{i:02}.jpg`, via WS1's `uploadScanScreenshot(scanId, name, bytes, "image/jpeg")`, which returns the public URL (§15.3).
  - Fallback while that helper is missing: `db().storage.from("scan-screenshots").upload(path, bytes, { contentType, upsert: true })` plus `getPublicUrl(path).data.publicUrl`, with a heads-up to WS1.
- It then pushes the URL to `probe.screenshots`, and pushes `{ i, action, reasoning, screenshot }` to `probe.steps`:
  - `action`: e.g. `"left_click (412, 230)"` or `"type 'hoodie'"`, joined with `"; "` for a batch.
  - `reasoning`: the first `thinking` summary or `text` block, ≤ 200 chars.
- Then it calls `ctx.update({ steps, screenshots, capabilities })`. That is about one `db.upsertScan` per turn (coalesced to ≤ 2/s), so the UI gets roughly one Realtime event per step.
- The same JPEG goes back to the model when the member was `screenshot`. Otherwise the model only sees screenshots it asks for.

**Cost and time** (`estimate.ts`). The price table is keyed by model. For `claude-opus-5-5` it is (UNVERIFIED — confirm on the pricing page) $5 input, $25 output, $6.25 cache write (1.25×) and $0.50 cache read (0.1×), per MTok.

```ts
usd = (input_tokens*5 + cache_creation_input_tokens*6.25 + cache_read_input_tokens*0.5 + output_tokens*25) / 1e6
      + minutes * costUsdPerMinute     // Browserbase ≈ $0.002/min; local 0
```

- The **measured** value from `usage` is what the probe reports.
- **Pre-run estimate**, shown while running, for a 15-turn worst case:
  - each turn adds ~1.3k image tokens + ~0.4k text;
  - cache reads Σ ≈ 200k tokens ≈ $0.10;
  - cache writes ≈ 27k tokens ≈ $0.17;
  - output, including thinking, ≈ 7.5k tokens ≈ $0.19;
  - **≈ $0.45 and 90–130 s**.
- Typical runs reach checkout in 8–10 turns: **≈ $0.25–0.35, 60–90 s**. This matches the headline "computer use ≈ 90 s / $0.30".
- Screenshot pruning is not needed at 15 turns. The docs suggest keeping the last 3 when loops run longer.

**Safety:**
- One fresh browser session per probe, with no credentials, no cookies from other runs, and captcha solving off.
- The navigation guard and the robots/SSRF guard (§6.4) apply.
- The payment guard makes the probe **structurally unable** to click pay buttons or type into payment fields.
- A detected challenge page ends the probe as `blocked`.

### 6.7 `checks.ts`: readiness checks inside the scan

`ScanReport.checks` are the 8 `ReadinessCheck`s with 00's `READINESS_WEIGHTS`, computed for the store as it is. They run **in parallel with the `api` probe** (budget 20 s), share the scan fetcher, and fill `ctx.shared` for the `dom` probe:

| id | "before" rule (network) |
|---|---|
| `products_json` | `GET {base}/products.json?limit=1` → 200 JSON with a `products` array |
| `well_known_ucp` | `GET {origin}/.well-known/ucp` → 200 JSON with a string `ucp.version` |
| `mcp_endpoint` | The UCP profile advertises an `mcp` transport, or `/.well-known/mcp/server-card.json` → 200 JSON |
| `llms_txt` | `GET {origin}/llms.txt` → 200, trimmed body starts with `#` and not `<` |
| `jsonld_product_coverage` | `discoverProductUrls` (≤ 3 sitemap fetches), sample 3 product pages (kept in `ctx.shared.pdpSample`) → at least 2 of 3 have a JSON-LD Product with a price. Detail: `"2/3 product pages have JSON-LD Product with price"`. |
| `sitemap` | Discovery found ≥ 1 product URL via sitemap (`source !== "html_links"`) |
| `robots_allows_agents` | `robots.isAllowed(firstProductUrl ?? base + "/", ua)` for `ShoperZeroBot`, `GPTBot`, `ClaudeBot`, `OAI-SearchBot` and `PerplexityBot`, and Content-Signal is not `ai-input=no`. The detail lists the blocked agents. |
| `agent_checkout` | The UCP profile declares `dev.ucp.shopping.checkout` |

`detail` is always set, ≤ 120 chars, and human readable. The checks are always all 8, in 00's `READINESS_CHECK_IDS` order.

### 6.8 `score.ts`: score, grade, after, recommendations

```ts
export type MethodClass = "api_standard" | "api_platform" | "dom" | "computer_use" | "none";
export const BAND: Record<MethodClass, number>   = { api_standard: 45, api_platform: 20, dom: 15, computer_use: 5, none: 0 };
export const FACTOR: Record<MethodClass, number> = { api_standard: 1.0, api_platform: 0.7, dom: 0.6, computer_use: 0.3, none: 0 };
export const CAPABILITY_WEIGHTS: Record<keyof Capabilities, number> =
  { catalog: 7, product_detail: 5, price_availability: 8, variants: 4, cart: 6, checkout_reachable: 5 };   // sum 35
export const CHECKS_SHARE = 0.20;                                           // max 20 points

export function methodClass(best: AccessProbe | null): MethodClass;         // api → standard iff a standard-class signal (§6.3) set a capability
export function scoreScan(input: { probes: AccessProbe[]; checks: ReadinessCheck[] }):
  { best_method: AccessMethod | "none"; method_class: MethodClass; score: number; grade: ReadinessGrade };
export function projectAfter(input: { best_method: AccessMethod | "none"; store: Store; checks: ReadinessCheck[] }):
  { score: number; grade: ReadinessGrade } | null;
export function afterReadiness(store: Store, stats: IndexStats): ReadinessReport;   // used by computeReadiness(store, "after")
export function afterScore(store: Store, stats: IndexStats): { score: number; grade: ReadinessGrade };
export function recommendations(r: Pick<ScanReport, "probes" | "checks" | "best_method" | "after">, store: Store): string[];
```

**Score:**

```
checksScore = Σ READINESS_WEIGHTS[c.id] for passing checks           (0..100, 00 weights)
S = BAND[class] + Σ_cap CAPABILITY_WEIGHTS[cap] × FACTOR[class] × [cap on the best probe]  +  CHECKS_SHARE × checksScore
score = clamp(round(S), 0, 100);  grade = gradeFor(score)             // 00: ≥90 A, ≥75 B, ≥60 C, ≥40 D, else F
```

- Capabilities count only from the **best** probe; other probes don't add points.
- `api_standard` = the best probe is `api` and at least one capability came from `ucp_*`, `mcp_endpoint`, `acp_feed`, `products_json` or `shopify_cart`. Otherwise an `api` best is `api_platform`: the agent has to know the platform's private API, and there is nothing it can discover.

**Expected scores** (these go into unit tests; the checks scores assume the typical results shown):

| Store | Class | Capabilities | Checks | Score → grade |
|---|---|---|---|---|
| Shopify (skullcandy) | api_standard | all 6 (35) | 100 → 20 | **100 → A** (control) |
| Typical Woo (porterandyork) | api_platform | all 6 → 35 × 0.7 = 24.5 | jsonld 15 + sitemap 10 + robots 10 = 35 → 7 | 20 + 24.5 + 7 = **52 → D** |
| Squarespace (hester-demo) | api_platform | catalog, detail, price, variants = 24 → 16.8 | ≈ 20 → 4 | **41 → D** |
| Custom JSON-LD store, recipe verified | dom | all 6 → 21 | 35 → 7 | **43 → D**. Without cart/checkout: 15 + 14.4 + 7 = **36 → F** |
| JS-only store, reached checkout by computer use | computer_use | 5 caps (no variants) = 31 → 9.3 | robots 10 → 2 | **16 → F** |
| Bot-walled (hellyhansen) | none | none | ≤ 20 | **≤ 4 → F** |

**After (via ShoperZero).** Once the catalog is indexed, agents use **our** standard surfaces: `products.json`, UCP, MCP, `llms.txt` and the feed. The after score uses the same formula with class `api_standard` and:
- `catalog`, `product_detail`, `price_availability` and `variants` all true (our API exposes all four);
- `cart` and `checkout_reachable` true when `resolveCheckoutConnector(store) !== "handoff"`;
- for `handoff`: `checkout_reachable` true (the `continue_url` reaches the merchant checkout) and `cart` false;
- checks: the "after" checks of §9.

| Case | After score |
|---|---|
| Our Woo demo store (`woo_store_api`) | 45 + 35 + 20 = **100 → A** |
| Any other indexed store (handoff) | 45 + 29 + (90 × 0.2 = 18) = **92 → A** |

- `projectAfter` runs before indexing. It assumes indexing succeeds with complete offers, and returns **`null`** when `best_method` is `computer_use` or `none` (no catalog to index; DECISIONS A). The UI then shows "Reachable by computer use only".
- `afterScore` (the actual value) runs at crawl finalize from `getIndexStats` and overwrites `scans.after`.

**Recommendations** (`string[]`, ≤ 6, in this priority order, each emitted only when its condition holds):
1. `best_method === "none"` and any probe is `blocked`: "Your site blocks automated agents (bot protection or robots.txt). AI assistants can't shop here; allowlist verified agents or publish a feed."
2. `best_method === "computer_use"`: "Agents can only use your store by looking at screenshots: about {s} s and ${usd} per task, versus about 1 s and $0.00 with an API. Add structured product data and an agent endpoint."
3. `well_known_ucp` fails: "Publish a UCP profile at /.well-known/ucp so agents can discover your catalog and checkout. ShoperZero hosts one for you at {store.urls.ucp}."
4. `products_json` and `acp_feed` both fail: "Expose a machine-readable catalog (products.json or an ACP feed). ShoperZero serves {store.urls.products_json}."
5. `jsonld_product_coverage` fails: "Add schema.org Product + Offer JSON-LD (price, priceCurrency, availability) to every product page."
6. `robots_allows_agents` fails: "robots.txt blocks {agents}; allow them if you want AI assistants to recommend and buy your products."
7. The best probe's `cart` is false: "Agents can't add to cart without a browser. Enable a headless cart API (e.g. WooCommerce Store API) or let ShoperZero hand off with a prefilled cart link."
8. `mcp_endpoint` fails: "Offer an MCP endpoint; ShoperZero provides one at {store.urls.mcp}."
9. `llms_txt` fails: "Add /llms.txt describing how agents should shop your store."
10. `sitemap` fails: "Publish a product sitemap listed in robots.txt."
11. **Always last**, when `after` is not null: "Make it agent-ready: ShoperZero indexes your catalog and serves UCP/MCP endpoints (projected grade {after.grade})."

### 6.9 `run.ts`: orchestration, budgets, failures

```ts
export async function runScan(scanId: string): Promise<ScanReport>   // never throws
```

1. **Load and claim.** `scan = await db.getScan(scanId)`. If it is missing, return an in-memory failed report. Claim it with `db.upsertScan({ id, status: "running" })`, but only from `queued` (`claimScan`, §15.3). Losing the claim → return the current report.
2. **Setup.**
   - `store = await db.getStoreById(scan.store_id)`; `target = storeTarget(store)`.
   - `scanDeadline = start + 270_000`.
   - `fetcher = createFetcher({ deadline: scanDeadline })`.
   - `robots = await loadRobots(...)`.
   - `detection = await detectPlatform(...)`, then `db.upsertScan({ id, platform })` and `db.updateStore(store.id, { platform })` when the stored platform is `unknown`.
3. **Blocked early exit.** If `robots.blocksUs`, or the homepage is challenged or forbidden, mark every probe `blocked` with `error.code` set to `robots` / `content_signal` / `challenge`. Skip the cascade and go to step 6. Computer use is **not** attempted, because we never try to bypass bot protection.
4. **Checks and the api probe.** Start `checks.ts` (20 s) and the `api` probe (25 s) concurrently with `Promise.allSettled`. Each api signal is pushed to `probes[0].signals` as it resolves.
5. **Cascade.**
   - **Order and budgets:** `api` (25 s), then `dom` (70 s), then `computer_use` (150 s, but never past `scanDeadline − 5 s`).
   - Each probe runs under `AbortSignal.timeout(budget)`, and `ctx.update` persists status changes and signals (≤ 2 writes/s).
   - **Stop** at the first `passed`. Mark every later method `skipped` with `error: { code: "cascade_stopped", message: "An earlier method passed." }`.
   - **Probe exceptions or timeouts** → that probe is `failed` with `error { code: "timeout" | "probe_error", message }`, and the cascade continues.
   - **Blocked mid-cascade:** a probe that sees a challenge is `blocked`, and the next method still runs, except that `computer_use` is skipped when the homepage itself is challenged.
   - **`mode: "full"`** (stretch) runs all three regardless, with the same budgets. The 270 s deadline still caps the total, and a probe that can't start in time is `skipped` with `time_budget`.
6. **Score.** `scoreScan()`, `projectAfter()` and `recommendations()` feed `db.upsertScan({ id, status: "done", best_method, score, grade, checks, after, recommendations })`.
7. **Store side-effects:**
   ```ts
   db.updateStore(store.id, { best_method, latest_scan_id: scan.id, dom_recipe, metadata: { ...metadata, computer_use_only: best_method === "computer_use" } })
   ```
   `dom_recipe` is written only when a recipe was verified (§6.5). Then `db.setStoreReadiness(store.id, "before", await computeReadiness(store, "before"))`.
8. **Infrastructure failure.** A DB error or an unexpected throw outside the probes → `db.upsertScan({ id, status: "failed" })`, with the error recorded on the running probe. The UI shows "Scan failed, retry". Always return the last known report.
9. **Stale scans.** A scan still `running` more than 6 minutes after `created_at` is treated as dead. `startScan` creates a new one and marks the old one `failed` (§15.3 `supersedeScans`).

**Worst-case timing:** detect ~10 s, then api 25 s, dom 70 s and computer use 150 s → about 255 s. That is under the 270 s scan deadline and the 300 s `maxDuration`.

### 6.10 How indexing reuses the scan

See §5.9 step 0 and §5.11 step 5.

| `best_method` | What indexing does |
|---|---|
| `api` (platform) | Locks straight onto the named adapter |
| `api` (Shopify `products.json`) | Uses the Shopify passthrough adapter |
| `dom` | Runs the T2 sitemap + JSON-LD engine, plus the stored recipe tier (stretch, CCR §15.8) |
| `computer_use` | Is not indexed. `POST /api/v1/stores` returns **422 `unprocessable`**, and the store is marked `best_method='computer_use'` / `metadata.computer_use_only = true` |
| `none` | 422 unless `force` |

The crawl also refreshes `scans.after` with the actual score (§5.10 step 7).

### 7.1 `src/app/api/v1/stores/route.ts`: GET + POST (WS2 owns both, B1)

```ts
export const maxDuration = 300;                     // after() crawl scheduling
export const OPTIONS = preflight;

const ListQuery = z.object({

const IndexBody = z.union([
  z.object({ url: z.string().trim().min(3).max(2048), max_products: z.number().int().min(1).max(500).optional(), force: z.boolean().optional() }).strict(),

]);
export const POST = route("stores.index", async (req, _ctx, { requestId }) => {
```

**Request** (accepted WS5 request): either `{ url, max_products?, force? }` or `{ store_id, max_products?, force? }`. The scan page's "Make it agent-ready" sends `{ store_id }`.

**Response** (`IndexStoreResult`, §15.1):

```json
{
  "store": { "id": "7c1e…", "slug": "bulk-com-uk", "domain": "bulk.com/uk", "base_url": "https://www.bulk.com/uk", "status": "crawling", "…": "…" },

  "status": "queued",
  "reused": false,
```

| Status | When |
|---|---|
| **202** | a new crawl was started |
| **200** | `cached: true`: an active run was reused, or the store was indexed (or blocked) in the last 6 h and `force` was not set |

### 7.3 `src/app/api/v1/scans/route.ts`: POST

```ts
export const maxDuration = 300;                     // runScan runs inside after()
export const OPTIONS = preflight;
const ScanBody = z.object({ url: z.string().trim().min(3).max(2048), mode: z.enum(["cascade", "full"]).optional() }).strict();
export const POST = route("scans.create", async (req, _ctx, { requestId }) => {
  const { url, mode } = await parseJsonBody(req, ScanBody);
  const r = await startScan(url, { mode });
  const { reused, ...body } = r;                    // body: { scan_id, store_id, status_url, report_url }
  return json(body, { status: reused ? 200 : 202, requestId, headers: { Location: r.status_url } });
});
```

**`startScan(url, { mode = "cascade" })`:**
1. **Store.** `normalizeStoreUrl` (a failure → `validation_error`), then `assertPublicHost`, then `db.upsertStoreForUrl(url)`. An opted-out store → `forbidden`.
2. **Reuse.** If there is an active scan for the store (`queued` or `running`, created under 6 min ago), return it with `reused: true`.
3. **Concurrency.** If `db.countActiveScans(6) >= SCAN_MAX_CONCURRENT`, throw `rate_limited`.
4. **Insert.** `db.upsertScan({ store_id, url: store.base_url, mode, status: "queued", platform: store.platform, best_method: "none", probes: [emptyProbe("api"), emptyProbe("dom"), emptyProbe("computer_use")], score: 0, grade: "F", checks: [], after: null, recommendations: [] })`, then `db.updateStore(store.id, { latest_scan_id })`.
5. **Schedule.** `after(() => runScan(scan.id))`.
6. **Return** `{ scan_id, store_id, status_url: \`${appUrl()}/api/v1/scans/${id}\`, report_url: \`${appUrl()}/scan/${id}\`, reused }`. `report_url` is WS5's page.

**Response (202):**

```json
{
  "scan_id": "5d2e…",
  "store_id": "7c1e…",
  "status_url": "https://<app>/api/v1/scans/5d2e…",
  "report_url": "https://<app>/scan/5d2e…"
}
```

**Codes:**

| Status | When |
|---|---|
| 202 | a new scan was queued |
| 200 | an active scan was reused |
| 400 | `bad_request` / `validation_error` |
| 403 | `forbidden` |
| 429 | `rate_limited` |
| 500 | `internal` |

## 8. MCP registrar: `registerCrawlTools` (`src/lib/crawl/mcp-tools.ts`)

WS3's `/api/mcp` route composes the registrars (B4, 00 §6.9). WS2 registers exactly four tools with `server.registerTool(name, { title, description, inputSchema, annotations }, handler)`. The handlers return 00's `toolResult(structured, summary)` and catch with `toolError(err, tool)`. **`structuredContent` equals the REST twin's body.**

**Logging.** WS3's `instrumentServer(server)` wraps every registrar in `/api/mcp`. It is the **only** place tool calls are logged to `agent_requests` (and where per-tool rate limiting lives). `registerCrawlTools` must **not** call `logAgentRequest`, and must not add its own logging or rate limiting. It only registers tools.

**Input schemas.**
- `index_store` and `get_crawl_status` use 00's `IndexStoreInputSchema` and `GetCrawlStatusInputSchema`, which match 03's `IndexStoreArgs` and `z.object({ crawl_run_id: z.uuid(), meta })`.
- `scan_store` and `get_scan` use new schemas, requested in §15.1:

```ts
export const ScanStoreInputSchema = z.object({
  url: z.string().trim().min(3).max(2048).describe('Store homepage URL or domain, e.g. "https://www.bulk.com/uk" or "bulk.com".'),
  mode: z.enum(["cascade", "full"]).optional().describe('Default "cascade": stop at the first access method that works.'),
  meta: UcpMetaSchema,
});
export const GetScanInputSchema = z.object({ scan_id: z.uuid().describe("From scan_store."), meta: UcpMetaSchema });
```

| Tool | Title | Annotations | Handler | `structuredContent` | Summary text |
|---|---|---|---|---|---|
| `index_store` | Index a new store | `{ readOnlyHint: false, destructiveHint: false, idempotentHint: true, openWorldHint: true }` | `startStoreCrawl(args.url)` | `{ store, crawl_run_id, status, reused, cached }` (the §7.1 body) | If `cached` and the store is `indexed`: `Already indexed recently. Search it now: search_catalog with catalog.store = "<slug>".` Otherwise: `Call get_crawl_status with crawl_run_id every 5-10 s.` |
| `get_crawl_status` | Crawl progress | `{ readOnlyHint: true }` | `getCrawlRun(id)` (`not_found` if null) and `getStoreById(run.store_id)` for the summary | `CrawlRun` (the §7.2 body) | While running: `Still crawling. Check again in 5-10 seconds.` On success: `Search it: search_catalog with catalog.store = "<slug>".` On failure: `Crawl failed: <error>. The store may block automated access.` |
| `scan_store` | Scan a store's agent readiness | `{ readOnlyHint: false, destructiveHint: false, idempotentHint: true, openWorldHint: true }` | `startScan(args.url, { mode })` | `{ scan_id, store_id, status_url, report_url }` | `Scan started. Call get_scan with scan_id every 5-10 s (typically 10-120 s). Human report: <report_url>` |
| `get_scan` | Scan result | `{ readOnlyHint: true }` | `getScanReport(id)` (`not_found` if null) | `ScanReport` | Running: `Scanning (<method> <status>)…`. Done: `Grade <grade> (<score>/100), best method <best_method>. <first recommendation>` |

**Tool descriptions** (the first two are verbatim from 03 §4.5–4.6):

`index_store`:
```
Ask ShoperZero to index a store that list_stores does not return, by its homepage URL. Any platform works; Shopify stores are passed through.
This starts an asynchronous crawl and returns immediately with the store record and a crawl_run_id. Poll get_crawl_status every 5-10 seconds until status is "succeeded" or "failed" (typically 30-120 seconds, up to about 150 products), then search it with search_catalog using store.slug.
Crawls respect the merchant's robots.txt. Stores behind bot protection finish with store status "blocked"; tell the buyer to use the merchant's site directly.
```

`get_crawl_status`:
```
Check the progress of a crawl started by index_store. Returns status (queued, running, succeeded, failed), products found so far, pages fetched, any error, and the store's current status. When done is true and the store status is "indexed", search it with search_catalog using store.slug.
```
(The output is the `CrawlRun` per 00; the "store status" and "done" information is in the summary text.)

`scan_store`:
```
Check how well an AI agent can use a store, by its homepage URL. ShoperZero tries three access methods in order and stops at the first that works: api (UCP/MCP/products.json or a platform API), dom (reading page structure and following add-to-cart), computer_use (a vision model clicking a real browser; never goes past the cart and never pays).
Returns immediately with scan_id; poll get_scan every 5-10 seconds. The result has an Agent Readiness Score (0-100, grade A-F), per-method capabilities, estimated seconds and USD per agent task, and recommendations.
```

`get_scan`:
```
Get the result of scan_store: status (queued, running, done, failed), per-method probes with capabilities, the best method, score and grade, the projected grade after ShoperZero indexes the store, and recommendations. Call index_store to make the store agent-ready.
```

**Error mapping.** Handlers let `AppError` propagate to `toolError`, which uses 00's codes (`validation_error`, `forbidden`, `not_found`, `unprocessable`, `rate_limited`, `internal`). The round-1 codes from 03 (`invalid_input`, `upstream_error`) are not used; B11 governs.

```ts
export const registerCrawlTools: ToolRegistrar = (server) => {
  server.registerTool("scan_store", { title: "Scan a store's agent readiness", description: SCAN_STORE_DESC,
    inputSchema: ScanStoreInputSchema, annotations: { readOnlyHint: false, destructiveHint: false, idempotentHint: true, openWorldHint: true } },
    async (args) => {
      try {
        const { reused: _r, ...out } = await startScan(args.url, { mode: args.mode });
        return toolResult(out, `Scan started. Call get_scan with scan_id every 5-10 s (typically 10-120 s). Human report: ${out.report_url}`);
      } catch (err) { return toolError(err, "scan_store"); }
    });
  // index_store, get_crawl_status, get_scan: same pattern (table above)
};
```

## 9. Readiness: `computeReadiness(store, phase)` (`src/lib/readiness/index.ts`, B2)

```ts
export const computeReadiness: ComputeReadinessFn = async (store, phase) => { … };   // (Store, "before" | "after") => Promise<ReadinessReport>
```

**`"before"`** is derived from the latest `ScanReport` (B2):
1. `scan = await db.getLatestScanForStore(store.id)` with `status === "done"`.
2. If found, return `{ score: scan.score, grade: scan.grade, checks: scan.checks, computed_at: scan.updated_at }`.
   - The headline number everywhere is the **Agent Readiness Score** (§6.8), so the store page and the scan page show the same grade.
   - `checks` are the 8 as-is checks. §15.1 asks 00 to update the `ReadinessReport.score` comment accordingly.
3. If there is no finished scan, run `runScan` synchronously on a fresh queued scan (`startScan` without `after()`, cascade limited to the `api` probe, 45 s budget), and derive the report from it.

**`"after"`** is computed from DB state with no network call. `stats = await db.getIndexStats(store.id)`, then `afterReadiness(store, stats)`, whose score is `afterScore()` (§6.8). The checks are:

| id | "After" rule (via ShoperZero) |
|---|---|
| `products_json` | `stats.product_count > 0` (WS3 serves `/s/{slug}/products.json`); detail = `store.urls.products_json` |
| `well_known_ucp` | `product_count > 0` (WS3 serves `/s/{slug}/.well-known/ucp`) |
| `mcp_endpoint` | always passes (`/api/mcp`) |
| `llms_txt` | `product_count > 0` |
| `jsonld_product_coverage` | `stats.offers_complete_ratio ≥ 0.8`; detail `"N/M products with live price + availability"` |
| `sitemap` | `product_count > 0` |
| `robots_allows_agents` | always passes (our `robots.txt`) |
| `agent_checkout` | `resolveCheckoutConnector(store) !== "handoff"`. For handoff it fails, with detail `"Assisted checkout: prefilled cart link"`. |

This gives 90 for handoff stores and 100 for the Woo demo store.

The crawl writes `before` (scan-derived) and `after` through `db.setStoreReadiness(id, phase, report)`. `Store.readiness` stays `{ before?, after? }` as in 00.
